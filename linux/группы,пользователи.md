# Практическое задание: пользователи и группы в Linux

## Цель

Цель задания — научиться работать с пользователями и группами в Linux через терминал. После выполнения задания вы будете понимать, как создаются пользователи, как назначаются пароли, как создаются группы, как пользователь добавляется в группу, где хранится информация о пользователях и группах, а также как проверить результат своей работы с помощью команд Linux.

В этом задании нужно не просто выполнить команды, а показать понимание того, что происходит в системе при создании пользователей и групп.

## Практическое задание

Представьте, что вы администратор Linux-сервера в учебной организации. Вам нужно подготовить систему для небольшой команды студентов и преподавателя.

Нужно создать пользователей, группы, назначить пользователей в группы и проверить, что всё настроено правильно.

### Шаг 1. Проверьте текущего пользователя

Выполните команду:

```bash
whoami
```

Затем проверьте, есть ли у вашего пользователя права администратора:

```bash
sudo -v
```

Если команда не вывела ошибку, значит, вы можете выполнять административные команды через `sudo`.

### Шаг 2. Создайте группы

Создайте две группы:

```bash
sudo groupadd students
sudo groupadd teachers
```

Проверьте, что группы появились в системе:

```bash
getent group students
getent group teachers
```

### Шаг 3. Создайте пользователей

Создайте трёх пользователей: `student1`, `student2`, `teacher1`.

```bash
sudo useradd -m -s /bin/bash student1
sudo useradd -m -s /bin/bash student2
sudo useradd -m -s /bin/bash teacher1
```

После этого проверьте, что пользователи появились:

```bash
getent passwd student1
getent passwd student2
getent passwd teacher1
```

### Шаг 4. Назначьте пароли пользователям

Назначьте пароли каждому пользователю:

```bash
sudo passwd student1
sudo passwd student2
sudo passwd teacher1
```

Во время ввода пароль не будет отображаться в терминале. Это нормально.

### Шаг 5. Добавьте пользователей в группы

Добавьте студентов в группу `students`:

```bash
sudo usermod -aG students student1
sudo usermod -aG students student2
```

Добавьте преподавателя в группу `teachers`:

```bash
sudo usermod -aG teachers teacher1
```

Проверьте группы каждого пользователя:

```bash
groups student1
groups student2
groups teacher1
```

### Шаг 6. Создайте общие директории для групп

Создайте директории:

```bash
sudo mkdir -p /study/students
sudo mkdir -p /study/teachers
```

Назначьте владельцем группы соответствующие группы:

```bash
sudo chown root:students /study/students
sudo chown root:teachers /study/teachers
```

Настройте права доступа:

```bash
sudo chmod 770 /study/students
sudo chmod 770 /study/teachers
```

Проверьте результат:

```bash
ls -ld /study/students
ls -ld /study/teachers
```

### Шаг 7. Проверьте домашние директории пользователей

Проверьте, появились ли домашние директории:

```bash
ls -ld /home/student1
ls -ld /home/student2
ls -ld /home/teacher1
```

### Шаг 8. Посмотрите системные файлы пользователей и групп

Найдите созданных пользователей в файле `/etc/passwd`:

```bash
grep 'student1' /etc/passwd
grep 'student2' /etc/passwd
grep 'teacher1' /etc/passwd
```

Найдите созданные группы в файле `/etc/group`:

```bash
grep 'students' /etc/group
grep 'teachers' /etc/group
```

### Шаг 9. Проверьте вход под другим пользователем

Переключитесь на пользователя `student1`:

```bash
su - student1
```

Проверьте, кто вы сейчас:

```bash
whoami
```

Проверьте текущую директорию:

```bash
pwd
```

Проверьте группы:

```bash
groups
```

Выйдите обратно:

```bash
exit
```

### Шаг 10. Удалите тестового пользователя

Создайте временного пользователя:

```bash
sudo useradd -m testuser
```

Проверьте его наличие:

```bash
getent passwd testuser
```

Удалите пользователя вместе с домашней директорией:

```bash
sudo userdel -r testuser
```

Проверьте, что пользователь удалён:

```bash
getent passwd testuser
ls -ld /home/testuser
```

Если пользователь и домашняя директория не найдены, значит удаление выполнено правильно.

## Подсказки по ключевым частям

В Linux каждый пользователь имеет свою учётную запись. Учётная запись нужна для того, чтобы система понимала, кто выполняет команды, какие файлы этому пользователю принадлежат и какие действия ему разрешены. Когда пользователь входит в систему, Linux определяет его имя, идентификатор пользователя, домашнюю директорию, оболочку и группы, в которые он входит.

Команда `whoami` показывает имя текущего пользователя. Это простая, но важная команда, потому что перед выполнением административных действий нужно понимать, от чьего имени вы работаете. Например, обычный пользователь не может создавать других пользователей без дополнительных прав.

Для выполнения административных команд используется `sudo`. Эта команда позволяет временно выполнить действие с правами суперпользователя. Например, создание пользователей, изменение паролей, создание системных директорий и изменение владельцев файлов требуют повышенных прав. Если забыть `sudo`, команда чаще всего завершится ошибкой `Permission denied`.

Пользователи в Linux создаются командой `useradd`. Например:

```bash
sudo useradd -m -s /bin/bash student1
```

Здесь `student1` — имя нового пользователя. Параметр `-m` означает, что для пользователя нужно создать домашнюю директорию. Обычно она создаётся по пути `/home/имя_пользователя`. Например, для пользователя `student1` это будет `/home/student1`.

Параметр `-s /bin/bash` указывает оболочку пользователя. Оболочка — это программа, через которую пользователь вводит команды. В большинстве учебных примеров используется `/bin/bash`, потому что это распространённая командная оболочка Linux.

Если создать пользователя без параметра `-m`, домашняя директория может не появиться. Поэтому в учебных и практических заданиях лучше явно указывать `-m`, чтобы результат был понятным и проверяемым.

Информация о пользователях хранится в файле `/etc/passwd`. Несмотря на название, пароли в открытом виде там не хранятся. В этом файле находятся основные сведения о пользователях: имя, UID, GID, комментарий, домашняя директория и оболочка. Посмотреть запись конкретного пользователя можно так:

```bash
grep 'student1' /etc/passwd
```

Пример строки может выглядеть так:

```text
student1:x:1001:1001::/home/student1:/bin/bash
```

Первая часть — имя пользователя. Символ `x` означает, что пароль хранится не здесь, а в защищённом файле `/etc/shadow`. Числа после этого — идентификаторы пользователя и основной группы. Затем указывается домашняя директория и оболочка.

Пароль пользователю назначается командой:

```bash
sudo passwd student1
```

При вводе пароля символы не отображаются. Это сделано специально для безопасности. Даже звёздочки обычно не показываются.

Группы в Linux нужны для управления правами сразу для нескольких пользователей. Например, если несколько студентов должны иметь доступ к одной директории, удобнее создать группу `students`, добавить туда пользователей и настроить права доступа для всей группы. Тогда не нужно выдавать права каждому пользователю отдельно.

Группа создаётся командой:

```bash
sudo groupadd students
```

Проверить наличие группы можно через:

```bash
getent group students
```

Также информация о группах хранится в файле `/etc/group`. Найти группу можно командой:

```bash
grep 'students' /etc/group
```

Команда `getent` часто удобнее, чем прямое чтение файлов, потому что она обращается к системной базе данных. В простых случаях она покажет данные из `/etc/passwd` или `/etc/group`, но в более сложных системах может учитывать и другие источники пользователей, например LDAP.

Чтобы добавить пользователя в дополнительную группу, используется команда `usermod`:

```bash
sudo usermod -aG students student1
```

Здесь важно понимать параметры. Ключ `-G` задаёт список дополнительных групп пользователя. Ключ `-a` означает append, то есть «добавить к уже существующим группам». Если использовать `-G` без `-a`, можно случайно заменить список дополнительных групп пользователя и удалить его из старых групп. Поэтому для добавления в группу обычно используют именно `-aG`.

Проверить группы пользователя можно командой:

```bash
groups student1
```

Если пользователь уже вошёл в систему, новые группы могут не примениться в текущей сессии сразу. В таком случае пользователю нужно выйти и войти снова. При проверке через `groups имя_пользователя` система обычно показывает актуальную информацию.

Домашняя директория пользователя — это его личное место для файлов. Обычно она находится в `/home`. Например:

```bash
/home/student1
/home/student2
/home/teacher1
```

Проверить наличие директории можно командой:

```bash
ls -ld /home/student1
```

Ключ `-l` показывает подробную информацию, а `-d` показывает сведения о самой директории, а не о её содержимом.

Права доступа в Linux связаны с пользователем-владельцем, группой-владельцем и остальными пользователями. Например, команда:

```bash
sudo chown root:students /study/students
```

означает, что владельцем директории будет пользователь `root`, а группой-владельцем будет `students`.

Команда `chmod` меняет права доступа. Например:

```bash
sudo chmod 770 /study/students
```

Число `770` означает, что владелец имеет полные права, группа имеет полные права, а остальные пользователи не имеют доступа. Первая цифра отвечает за владельца, вторая — за группу, третья — за остальных. Значение `7` означает чтение, запись и выполнение. Для директорий право выполнения означает возможность входить в директорию.

Команда `su - student1` позволяет переключиться на другого пользователя. Символ `-` важен, потому что он запускает полноценную пользовательскую сессию с домашней директорией и окружением этого пользователя. После переключения можно выполнить:

```bash
whoami
pwd
groups
```

Так можно убедиться, что вход выполнен от имени нужного пользователя.

Для удаления пользователя используется команда `userdel`. Если выполнить:

```bash
sudo userdel testuser
```

пользователь будет удалён, но его домашняя директория может остаться. Чтобы удалить пользователя вместе с домашней директорией, используется:

```bash
sudo userdel -r testuser
```

Ключ `-r` означает удаление связанных файлов, включая домашнюю директорию и почтовый ящик пользователя, если он есть.

При выполнении задания важно не просто копировать команды, а понимать, что именно меняется в системе. Создание пользователя добавляет запись в системную базу пользователей. Создание группы добавляет запись в базу групп. Добавление пользователя в группу меняет его права доступа. Настройка владельца и прав директории определяет, кто сможет читать, создавать и изменять файлы внутри неё.

## Что проверить перед отправкой

Перед отправкой работы проверьте, что группы действительно созданы:

```bash
getent group students
getent group teachers
```

Проверьте, что пользователи существуют:

```bash
getent passwd student1
getent passwd student2
getent passwd teacher1
```

Проверьте, что у пользователей есть домашние директории:

```bash
ls -ld /home/student1
ls -ld /home/student2
ls -ld /home/teacher1
```

Проверьте, что пользователи входят в правильные группы:

```bash
groups student1
groups student2
groups teacher1
```

Ожидаемый результат:

```text
student1 : student1 students
student2 : student2 students
teacher1 : teacher1 teachers
```

Формат вывода может немного отличаться, но группы `students` и `teachers` должны быть видны у соответствующих пользователей.

Проверьте права на директории:

```bash
ls -ld /study/students
ls -ld /study/teachers
```

Ожидаемый смысл результата:

```text
/study/students принадлежит группе students
/study/teachers принадлежит группе teachers
права доступа установлены как rwxrwx
```

Проверьте, что временный пользователь `testuser` удалён:

```bash
getent passwd testuser
ls -ld /home/testuser
```

Если команды не находят пользователя и директорию, значит удаление выполнено правильно.

В отчёте или ответе на проверку нужно показать команды, которые вы выполнили, и результаты проверок. Не нужно отправлять только команды без вывода, потому что по ним нельзя понять, действительно ли настройка была выполнена.

## Советы по улучшению работы

Старайтесь выполнять команды осознанно. Перед запуском команды подумайте, что она должна изменить в системе. Например, `groupadd` создаёт группу, `useradd` создаёт пользователя, `passwd` задаёт пароль, `usermod -aG` добавляет пользователя в дополнительную группу, `chown` меняет владельца, а `chmod` меняет права доступа.

Не используйте случайные имена пользователей и групп. В задании важно соблюдать точные имена: `student1`, `student2`, `teacher1`, `students`, `teachers`. Это упростит проверку.

После каждой важной команды сразу выполняйте проверку. Например, после создания группы используйте `getent group`, после создания пользователя — `getent passwd`, после добавления в группу — `groups`. Такой подход помогает быстрее находить ошибки.

Будьте осторожны с командой `userdel -r`. Она удаляет пользователя вместе с домашней директорией. Не применяйте её к реальным пользователям системы, если вы не уверены, что это безопасно.

Не редактируйте вручную файлы `/etc/passwd`, `/etc/group` и `/etc/shadow`, если этого не требует отдельное задание. Для учебной практики безопаснее использовать специальные команды `useradd`, `groupadd`, `usermod`, `passwd` и `userdel`.

Если команда не выполняется из-за ошибки прав доступа, проверьте, используете ли вы `sudo`. Если ошибка связана с тем, что пользователь или группа уже существует, значит команда ранее уже была выполнена. В таком случае переходите к проверке результата.

Для более аккуратной работы можно сохранять вывод команд в текстовый файл:

```bash
getent passwd student1 >> report.txt
getent passwd student2 >> report.txt
getent passwd teacher1 >> report.txt
groups student1 >> report.txt
groups student2 >> report.txt
groups teacher1 >> report.txt
ls -ld /study/students >> report.txt
ls -ld /study/teachers >> report.txt
```

Такой файл можно использовать как отчёт о выполнении практической работы.

Дополнительное улучшение: создайте внутри `/study/students` тестовый файл от имени одного из студентов и проверьте, что другой студент может его увидеть. Это покажет, что групповая настройка доступа действительно работает.

Пример:

```bash
su - student1
touch /study/students/student1_file.txt
exit
```

Затем:

```bash
su - student2
ls -l /study/students
exit
```

Если `student2` видит файл, значит доступ через группу работает.

Для преподавателя можно выполнить похожую проверку с директорией `/study/teachers`.

Главный результат задания — не просто наличие пользователей и групп, а понимание связи между пользователями, группами, домашними директориями и правами доступа в Linux.
