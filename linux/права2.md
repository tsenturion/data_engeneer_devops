# Практическое задание: права доступа, chmod, chown, chgrp, специальные права и sudo в Linux

## Цель

Цель практической работы — научиться управлять доступом к файлам и директориям в Linux. В этой работе вы будете использовать пользователей и группы, созданные в предыдущем задании: `student1`, `student2`, `teacher1`, группы `students` и `teachers`, а также директории внутри `/study`.

После выполнения задания вы будете понимать, как работают права `r`, `w`, `x`, чем отличаются права для файлов и директорий, как применять команды `chmod`, `chown`, `chgrp`, как читать числовую запись прав доступа вида `644`, `755`, `700`, зачем нужны специальные права SUID, SGID и sticky bit, а также как безопасно настраивать ограниченные административные права через `sudo` и `/etc/sudoers.d`.

## Практическое задание

Представьте, что после создания пользователей и групп вам нужно настроить права доступа для учебного пространства. Студенты должны иметь доступ к общей директории, преподаватель должен иметь отдельную директорию, часть файлов должна быть доступна только владельцу, а для некоторых директорий нужно настроить специальные права.

Работу выполняйте в терминале Linux. Большинство команд потребуется запускать через `sudo`.

### Шаг 11. Создайте безопасную демонстрацию SUID через небольшой C-код

Этот шаг нужен для понимания механизма SUID. Выполняйте его только в учебной среде.

Создайте файл с C-кодом:

```bash
cat > /tmp/showids.c <<'EOF'
#include <stdio.h>
#include <unistd.h>

int main() {
    printf("Real UID: %d\n", getuid());
    printf("Effective UID: %d\n", geteuid());
    return 0;
}
EOF
```

Скомпилируйте программу:

```bash
gcc /tmp/showids.c -o /tmp/showids
```

Если `gcc` не установлен, этот шаг можно пропустить и ограничиться просмотром `/usr/bin/passwd`.

Переместите программу в учебную директорию:

```bash
sudo mv /tmp/showids /study/permissions/showids
```

Сделайте владельцем файла пользователя `root`:

```bash
sudo chown root:root /study/permissions/showids
```

Установите SUID:

```bash
sudo chmod 4755 /study/permissions/showids
```

Проверьте права:

```bash
ls -l /study/permissions/showids
```

Запустите программу от имени `student1`:

```bash
sudo -u student1 /study/permissions/showids
```

Ожидаемый смысл результата: `Real UID` будет относиться к пользователю `student1`, а `Effective UID` может быть `0`, если SUID сработал. UID `0` — это root.

Если `Effective UID` не стал `0`, возможно, файловая система смонтирована с параметром `nosuid`. Это часто встречается в учебных, контейнерных или ограниченных средах.

После проверки обязательно уберите SUID и удалите демонстрационную программу:

```bash
sudo chmod u-s /study/permissions/showids
sudo rm /study/permissions/showids
```

## Подсказки по ключевым частям

В Linux права доступа определяют, кто может читать, изменять и запускать файлы, а также кто может заходить в директории и работать с их содержимым. Когда вы выполняете команду `ls -l`, Linux показывает права доступа в начале строки. Например:

```text
-rw-r--r--
```

Первый символ показывает тип объекта. Если это `-`, перед вами обычный файл. Если это `d`, перед вами директория. Дальше идут три группы прав: права владельца, права группы и права остальных пользователей.

Например, строка:

```text
-rw-r--r--
```

читается так: владелец может читать и изменять файл, группа может только читать, остальные пользователи тоже могут только читать.

Право `r` означает read, то есть чтение. Для файла это возможность открыть и прочитать содержимое. Для директории это возможность посмотреть список файлов внутри директории, но само по себе право `r` для директории не всегда достаточно. Чтобы нормально работать с директорией, часто нужно ещё и право `x`.

Право `w` означает write, то есть запись. Для файла это возможность изменять содержимое файла. Для директории это возможность создавать, удалять и переименовывать файлы внутри неё. Важно понимать, что удаление файла зависит не только от прав на сам файл, но и от прав на директорию, в которой он находится.

Право `x` означает execute, то есть выполнение. Для файла это возможность запустить файл как программу или скрипт. Например, если у файла `run.sh` нет права `x`, то его нельзя запустить напрямую командой:

```bash
./run.sh
```

Для директории право `x` означает возможность войти в директорию и обращаться к объектам внутри неё по имени. Поэтому для директорий право `x` очень важно. Директория без `x` может быть фактически недоступной, даже если у неё есть право `r`.

Команда `chmod` используется для изменения прав доступа. Например:

```bash
chmod 644 file.txt
```

Число `644` означает, что владелец получает права `rw-`, группа получает `r--`, остальные получают `r--`.

Числовая запись строится из трёх значений: владелец, группа, остальные. Каждое значение получается сложением чисел: `4` означает чтение, `2` означает запись, `1` означает выполнение.

Например, значение `7` получается как `4 + 2 + 1`, то есть чтение, запись и выполнение. Значение `6` получается как `4 + 2`, то есть чтение и запись. Значение `5` получается как `4 + 1`, то есть чтение и выполнение. Значение `0` означает отсутствие прав.

Права `644` часто используют для обычных текстовых файлов. Владелец может редактировать файл, остальные могут только читать.

Права `755` часто используют для директорий и исполняемых файлов. Владелец может читать, изменять и выполнять, а группа и остальные могут читать и выполнять. Для директории это означает, что пользователи могут заходить в неё и смотреть содержимое, но не могут создавать там новые файлы без права записи.

Права `700` используют для приватных файлов и директорий. Владелец имеет полный доступ, остальные пользователи не имеют доступа вообще.

Команда `chown` меняет владельца файла или директории. Например:

```bash
sudo chown student1 file.txt
```

Эта команда делает `student1` владельцем файла. Можно одновременно указать и пользователя, и группу:

```bash
sudo chown student1:students file.txt
```

После такой команды владельцем будет `student1`, а группой-владельцем будет `students`.

Команда `chgrp` меняет только группу-владельца:

```bash
sudo chgrp students file.txt
```

Это удобно, когда владелец должен остаться прежним, но файл нужно привязать к другой группе.

Специальные права в Linux расширяют обычную модель `r`, `w`, `x`. К ним относятся SUID, SGID и sticky bit.

SUID устанавливается на исполняемый файл. Если на программе установлен SUID, то при запуске она выполняется с эффективными правами владельца файла. Например, если программа принадлежит `root` и на ней стоит SUID, обычный пользователь может запустить её так, что часть действий будет выполняться с правами root. Именно поэтому SUID нужно использовать очень осторожно. Неправильно настроенная SUID-программа может стать серьёзной проблемой безопасности.

SGID может применяться к файлам и директориям. В этой практической работе важнее SGID на директории. Если на директории установлен SGID, новые файлы внутри неё наследуют группу этой директории. Это удобно для групповой работы. Например, если директория принадлежит группе `students` и на ней установлен SGID, новые файлы внутри неё тоже будут относиться к группе `students`.

Sticky bit чаще всего используется на общих директориях. Классический пример — `/tmp`. В такой директории разные пользователи могут создавать файлы, но удалять они могут только свои файлы. Sticky bit помогает избежать ситуации, когда один пользователь случайно или намеренно удаляет файл другого пользователя.

Команда `sudo` позволяет выполнять команды с повышенными правами. Обычно обычный пользователь не может изменять системные файлы, создавать пользователей, менять владельцев чужих файлов или настраивать sudoers. Но если пользователь входит в список доверенных, он может использовать `sudo`.

Файл `/etc/sudoers` и директория `/etc/sudoers.d` используются для настройки прав sudo. Важно не редактировать `/etc/sudoers` обычным текстовым редактором без проверки. Ошибка в синтаксисе может привести к тому, что sudo перестанет работать. Поэтому для проверки используется команда `visudo`.

В современных системах удобно создавать отдельные файлы правил в `/etc/sudoers.d`. Например, можно создать правило только для пользователя `teacher1`, не изменяя основной файл `/etc/sudoers`.

Пример правила:

```text
teacher1 ALL=(root) NOPASSWD: /usr/bin/id
```

Это означает, что пользователь `teacher1` может выполнять команду `/usr/bin/id` от имени `root` без ввода пароля. При этом он не получает полный административный доступ ко всей системе.

Важно выдавать пользователям только те права, которые им действительно нужны. Это называется принципом минимальных привилегий. Например, если преподавателю нужно только проверить системную информацию, не нужно давать ему полный доступ ко всем командам root.

## Что проверить перед отправкой

Перед отправкой работы проверьте, что директория практической работы создана:

```bash
ls -ld /study/permissions
```

Проверьте структуру директорий:

```bash
ls -l /study/permissions
```

Проверьте права публичного файла:

```bash
ls -l /study/permissions/public/readme.txt
```

Ожидается, что файл имеет права `644`.

Проверьте права скрипта:

```bash
ls -l /study/permissions/scripts/run.sh
```

Ожидается, что файл имеет права `755` и может запускаться.

Проверьте права личного файла:

```bash
ls -l /study/permissions/private/student1_secret.txt
```

Ожидается, что файл принадлежит `student1` и имеет права `700`.

Проверьте, что `student1` может прочитать свой личный файл:

```bash
sudo -u student1 cat /study/permissions/private/student1_secret.txt
```

Проверьте, что `student2` не может прочитать личный файл `student1`:

```bash
sudo -u student2 cat /study/permissions/private/student1_secret.txt
```

Проверьте SGID на групповой директории:

```bash
ls -ld /study/permissions/groupwork
```

Ожидается наличие `s` в правах группы:

```text
drwxrws
```

Проверьте, что новые файлы внутри `groupwork` получают группу `students`:

```bash
ls -l /study/permissions/groupwork
```

Проверьте sticky bit на директории `dropbox`:

```bash
ls -ld /study/permissions/dropbox
```

Ожидается наличие `t` в конце прав:

```text
drwxrwxrwt
```

Проверьте, что один студент не может удалить файл другого студента из `dropbox`.

Проверьте пример SUID на системной команде:

```bash
ls -l /usr/bin/passwd
```

В правах должна быть буква `s`.

Проверьте, что временное sudo-правило для `teacher1` было создано, протестировано и удалено:

```bash
sudo ls -l /etc/sudoers.d/
```

Если файл `/etc/sudoers.d/teacher1-limited` остался после проверки, удалите его:

```bash
sudo rm /etc/sudoers.d/teacher1-limited
```

В отчёте нужно показать команды и результаты проверок. Особенно важно показать вывод команд `ls -l`, `ls -ld`, `groups`, а также результаты проверки доступа от имени разных пользователей.

## Советы по улучшению работы

Старайтесь не просто выполнять команды, а объяснять, почему вы выбрали именно такие права. Например, `644` подходит для обычного файла, который должны читать многие пользователи, но изменять должен только владелец. Права `755` подходят для директорий и исполняемых файлов, которые должны быть доступны для входа или запуска. Права `700` подходят для личных файлов, к которым не должны иметь доступ другие пользователи.

После каждого изменения прав сразу проверяйте результат через `ls -l` или `ls -ld`. Это поможет быстрее заметить ошибку.

Не используйте слишком широкие права без необходимости. Например, `777` почти никогда не является хорошим решением для обычной рабочей директории. Исключение — специальные общие директории вроде `/tmp`, но там обычно используется sticky bit, то есть права выглядят как `1777`.

Будьте особенно осторожны с SUID. Никогда не ставьте SUID на случайные скрипты или программы, если не понимаете последствий. В учебной работе SUID используется только для демонстрации, после чего демонстрационную программу нужно удалить.

Не редактируйте `/etc/sudoers` напрямую обычным редактором. Используйте `visudo` или создавайте отдельные файлы в `/etc/sudoers.d` с обязательной проверкой синтаксиса.

Для отчёта можно сохранить результаты проверок в файл:

```bash
ls -ld /study/permissions >> permissions_report.txt
ls -l /study/permissions/public/readme.txt >> permissions_report.txt
ls -l /study/permissions/private/student1_secret.txt >> permissions_report.txt
ls -ld /study/permissions/groupwork >> permissions_report.txt
ls -ld /study/permissions/dropbox >> permissions_report.txt
ls -l /usr/bin/passwd >> permissions_report.txt
```

Дополнительно можно добавить в отчёт короткие объяснения:

```text
644 — владелец может читать и писать, остальные могут только читать.
755 — владелец имеет полный доступ, остальные могут читать и выполнять.
700 — доступ есть только у владельца.
SGID на директории нужен для наследования группы.
Sticky bit нужен, чтобы пользователи не удаляли чужие файлы в общей директории.
SUID позволяет программе выполняться с правами владельца файла.
```

Главный результат этой практической работы — умение связать пользователей, группы и права доступа в единую систему безопасности Linux.
