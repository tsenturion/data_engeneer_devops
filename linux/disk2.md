# Практическое задание. Swap, LVM, мониторинг и диагностика ресурсов Linux

## Цель

Научиться контролировать состояние ресурсов Ubuntu через терминал и SSH, работать со swap, определять структуру LVM, отслеживать загрузку CPU, оперативной памяти и дисковой подсистемы, создавать безопасную контролируемую нагрузку и диагностировать типичные проблемы нехватки дискового пространства и оперативной памяти.

В ходе работы необходимо закрепить команды и утилиты:

```bash
free
swapon
swapoff
mkswap
vmstat
uptime
nproc
lscpu
top
ps
pvs
vgs
lvs
mpstat
pidstat
iostat
stress-ng
df
du
find
journalctl
lsof
```

# Важные правила безопасности

Не использовать для экспериментов с LVM системный диск, на котором находится корневая файловая система `/`.

Перед работой с дисками обязательно выполнить:

```bash
findmnt /
```

и:

```bash
lsblk
```

Если `/` находится, например, на:

```text
/dev/sda2
```

то `/dev/sda` является системным диском и использовать его в командах `pvcreate`, `vgcreate`, `mkfs` нельзя.

Для LVM необходим отдельный учебный виртуальный диск.

Не создавать искусственную нехватку памяти до состояния OOM.

Не запускать `stress-ng` без ограничения времени.

Не заполнять корневую файловую систему до 100%.

Не выполнять:

```bash
sudo swapoff -a
```

если не известно, сколько swap реально используется.

Не использовать:

```bash
sudo rm -rf
```

для очистки системных каталогов.

# Часть 2. Работа со swap

## Шаг 1. Определить существующий swap

Выполните:

```bash
free -h
```

```bash
swapon --show
```

```bash
cat /proc/swaps
```

Посмотрите:

```bash
cat /etc/fstab
```

Определите, присутствует ли swap и каким способом он реализован:

```text
swap-файл
или
swap-раздел
```

Запишите:

```text
Тип swap:
Путь или устройство:
Размер:
Использовано:
```

# Шаг 2. Проверить swappiness

Выполните:

```bash
sysctl vm.swappiness
```

Затем:

```bash
cat /proc/sys/vm/swappiness
```

Значения должны совпасть.

Запишите текущее значение.

Изменять его постоянно в этом задании не требуется.

# Шаг 3. Создать дополнительный учебный swap-файл

Сначала обязательно проверить место:

```bash
df -h /
```

Если свободного пространства меньше 1 ГБ, используйте swap-файл размером 256 МБ.

Если места достаточно, создайте файл размером 512 МБ:

```bash
sudo fallocate -l 512M /swap-lab
```

Проверьте:

```bash
ls -lh /swap-lab
```

Установите безопасные права:

```bash
sudo chmod 600 /swap-lab
```

Проверьте:

```bash
ls -l /swap-lab
```

Подготовьте файл:

```bash
sudo mkswap /swap-lab
```

Активируйте:

```bash
sudo swapon /swap-lab
```

Проверьте:

```bash
swapon --show
```

И:

```bash
free -h
```

Зафиксируйте, как изменился общий объем swap.

# Шаг 4. Отключить учебный swap

Перед отключением убедитесь, что учебный swap не используется активно:

```bash
swapon --show
```

Отключите только созданный вами файл:

```bash
sudo swapoff /swap-lab
```

Проверьте:

```bash
swapon --show
```

Удалите учебный файл:

```bash
sudo rm /swap-lab
```

Убедитесь, что он удален:

```bash
ls -l /swap-lab
```

Ожидается сообщение о том, что такого файла нет.

Не отключайте штатный swap Ubuntu.

# Часть 3. Основы LVM

Для этой части используется отдельный учебный виртуальный диск.

Оптимальный вариант для VirtualBox — добавить диск размером:

```text
2–4 ГБ
```

Системный диск использовать запрещено.

# Вариант A. Есть отдельный учебный виртуальный диск

## Шаг 1. Определить диск

Выполните:

```bash
lsblk
```

И:

```bash
findmnt /
```

Пример:

```text
sda      30G disk
├─sda1
└─sda2      /

sdb       3G disk
```

В этом примере:

```text
/dev/sda
```

системный диск.

```text
/dev/sdb
```

учебный дополнительный диск.

У вас имя может отличаться.

Не копируйте `/dev/sdb` автоматически.

# Шаг 2. Проверить LVM до изменений

Выполните:

```bash
sudo pvs
```

```bash
sudo vgs
```

```bash
sudo lvs
```

Сохраните вывод.

# Шаг 3. Создать Physical Volume

Только после проверки правильного устройства:

```bash
sudo pvcreate /dev/sdb
```

Замените `/dev/sdb` своим учебным диском.

Проверьте:

```bash
sudo pvs
```

И:

```bash
sudo pvdisplay
```

# Шаг 4. Создать Volume Group

Создайте:

```bash
sudo vgcreate vg_lab /dev/sdb
```

Проверьте:

```bash
sudo vgs
```

И:

```bash
sudo vgdisplay vg_lab
```

Определите общий и свободный размер группы.

# Шаг 5. Создать Logical Volume

Создайте том размером 1 ГБ:

```bash
sudo lvcreate -L 1G -n lv_data vg_lab
```

Проверьте:

```bash
sudo lvs
```

И:

```bash
lsblk
```

Должен появиться логический том:

```text
/dev/vg_lab/lv_data
```

# Шаг 6. Создать файловую систему

Создайте `ext4`:

```bash
sudo mkfs.ext4 /dev/vg_lab/lv_data
```

Создайте точку монтирования:

```bash
sudo mkdir -p /mnt/lvm-lab
```

Смонтируйте:

```bash
sudo mount /dev/vg_lab/lv_data /mnt/lvm-lab
```

Проверьте:

```bash
findmnt /mnt/lvm-lab
```

И:

```bash
df -hT /mnt/lvm-lab
```

# Шаг 7. Создать тестовый файл

Посмотрите права:

```bash
ls -ld /mnt/lvm-lab
```

Если каталог принадлежит `root` и необходимо работать обычным пользователем:

```bash
sudo chown "$(whoami)":"$(id -gn)" /mnt/lvm-lab
```

Создайте:

```bash
echo "LVM practice" > /mnt/lvm-lab/test.txt
```

Проверьте:

```bash
cat /mnt/lvm-lab/test.txt
```

# Шаг 8. Расширить логический том

Сначала:

```bash
sudo vgs
```

Убедитесь, что внутри `vg_lab` осталось свободное место.

Проверьте текущий размер:

```bash
df -hT /mnt/lvm-lab
```

Расширьте LV еще на 512 МБ вместе с файловой системой:

```bash
sudo lvextend -r -L +512M /dev/vg_lab/lv_data
```

После:

```bash
sudo lvs
```

И:

```bash
df -hT /mnt/lvm-lab
```

Сравните размер до и после расширения.

# Часть 4. Базовый мониторинг ресурсов

## Шаг 1. Открыть два SSH-сеанса

Для студентов, работающих через SSH, рекомендуется открыть два терминала.

В первом будет запускаться нагрузка.

Во втором — мониторинг.

Если работа выполняется непосредственно в Linux, можно открыть два терминала.

# Шаг 2. Изучить `top`

Выполните:

```bash
top
```

Найдите:

```text
load average
%Cpu
MiB Mem
MiB Swap
```

Определите процесс, который в текущий момент использует больше всего CPU.

Выйдите:

```text
q
```

# Шаг 3. Получить снимок процессов

Самые активные по CPU:

```bash
ps -eo pid,ppid,user,comm,%cpu,%mem --sort=-%cpu | head -n 15
```

Самые активные по памяти:

```bash
ps -eo pid,ppid,user,comm,%mem,rss --sort=-rss | head -n 15
```

Сохраните результаты.

# Шаг 4. Использовать vmstat

Запустите:

```bash
vmstat 1 10
```

Обратите внимание на:

```text
r
b
si
so
bi
bo
us
sy
id
wa
```

Запишите, были ли ненулевые значения `si` и `so`.

Запишите примерное значение `id`.

# Шаг 5. Проверить CPU через mpstat

Выполните:

```bash
mpstat -P ALL 1 5
```

Определите:

```text
сколько CPU видно;
какой CPU был наиболее загружен;
какой был %idle.
```

# Шаг 6. Использовать pidstat

CPU:

```bash
pidstat -u 1 5
```

Память:

```bash
pidstat -r 1 5
```

Диск:

```bash
pidstat -d 1 5
```

Сохраните по одному примеру результата каждого режима.

# Часть 5. Контролируемая нагрузка на CPU

## Шаг 1. Зафиксировать состояние до нагрузки

Выполните:

```bash
uptime
```

```bash
mpstat -P ALL 1 3
```

# Шаг 2. Создать нагрузку

В первом терминале:

```bash
stress-ng --cpu 1 --timeout 30s --metrics-brief
```

Команда должна самостоятельно завершиться через 30 секунд.

# Шаг 3. Наблюдать во втором терминале

Одновременно используйте:

```bash
mpstat -P ALL 1 10
```

После можно повторить тест и наблюдать:

```bash
pidstat -u 1 10
```

Или:

```bash
top
```

Сравните показатели до нагрузки и во время нагрузки.

# Часть 6. Контролируемая нагрузка на память

## Шаг 1. Зафиксировать память до нагрузки

Выполните:

```bash
free -h
```

```bash
swapon --show
```

```bash
cat /proc/pressure/memory
```

# Шаг 2. Запустить умеренную нагрузку

Используйте:

```bash
stress-ng --vm 1 --vm-bytes 20% --timeout 30s --metrics-brief
```

Не увеличивайте `20%` до экстремальных значений.

# Шаг 3. Наблюдать

Во втором терминале:

```bash
vmstat 1 10
```

Затем при повторном тесте:

```bash
pidstat -r 1 10
```

Можно дополнительно:

```bash
free -h
```

Сравните:

```text
MemAvailable до;
MemAvailable во время нагрузки;
использованный swap;
si;
so.
```

Если `si` и `so` остаются около нуля, это нормальный результат для умеренной нагрузки.

Не требуется специально добиваться использования swap.

# Часть 7. Контролируемая нагрузка на диск

## Шаг 1. Проверить место

Перед тестом:

```bash
df -h /tmp
```

Не продолжайте, если свободного места недостаточно.

# Шаг 2. Посмотреть состояние диска

Выполните:

```bash
iostat -xz 1 3
```

Сохраните исходный результат.

# Шаг 3. Создать небольшую нагрузку

В первом терминале:

```bash
stress-ng --hdd 1 --hdd-bytes 128M --temp-path /tmp --timeout 30s --metrics-brief
```

Размер намеренно ограничен 128 МБ.

# Шаг 4. Наблюдать за I/O

Во втором терминале:

```bash
iostat -xz 1 10
```

Обратите внимание на устройство, где расположен `/tmp`.

Определить его можно:

```bash
df -hT /tmp
```

Сравните:

```text
операции чтения/записи;
await;
%util.
```

Дополнительно можно выполнить:

```bash
sudo iotop
```

Выйти из `iotop`:

```text
q
```

# Часть 8. PSI — давление на ресурсы

До нагрузки выполните:

```bash
cat /proc/pressure/cpu
```

```bash
cat /proc/pressure/memory
```

```bash
cat /proc/pressure/io
```

Сохраните минимум один пример:

```text
some avg10=...

```

# Часть 9. Диагностика нехватки дискового пространства

В этой части не нужно реально заполнять системный диск.

Диагностика выполняется на безопасно созданных учебных файлах.

## Шаг 1. Проверить файловую систему

Выполните:

```bash
df -hT
```

И:

```bash
df -i
```

Определите процент использования `/`.

# Шаг 2. Найти крупные каталоги

Выполните:

```bash
sudo du -xhd1 / 2>/dev/null | sort -h
```

Определите три наиболее крупных каталога верхнего уровня.

Затем исследуйте один из них.

Например, если крупный `/var`:

```bash
sudo du -xhd1 /var 2>/dev/null | sort -h
```

Не удаляйте найденные данные.

# Шаг 3. Создать безопасный учебный каталог

Создайте:

```bash
mkdir -p ~/disk-lab
```

Проверьте свободное место:

```bash
df -h ~
```

Создайте три учебных файла:

```bash
fallocate -l 32M ~/disk-lab/file1.bin
```

```bash
fallocate -l 64M ~/disk-lab/file2.bin
```

```bash
fallocate -l 96M ~/disk-lab/file3.bin
```

Проверьте:

```bash
ls -lh ~/disk-lab
```

# Шаг 4. Найти самый большой файл

Выполните:

```bash
du -h ~/disk-lab/*
```

Затем:

```bash
du -h ~/disk-lab/* | sort -hr
```

Используйте `find`:

```bash
find ~/disk-lab -type f -size +50M -ls
```

Определите, какие файлы превышают 50 МБ.

# Шаг 5. Сравнить df и du

Выполните:

```bash
du -sh ~/disk-lab
```

И:

```bash
df -h ~/disk-lab
```

# Шаг 6. Проверить systemd journal

Выполните:

```bash
journalctl --disk-usage
```

Только посмотреть результат.

Очищать системные журналы в этой практической работе не требуется.

# Шаг 7. Проверить удаленные, но открытые файлы

Выполните:

```bash
sudo lsof +L1
```

Если ничего не найдено, это нормальный результат.

Не требуется специально создавать такой проблемный процесс.

# Шаг 8. Удалить учебные данные

После завершения:

```bash
rm ~/disk-lab/file1.bin
```

```bash
rm ~/disk-lab/file2.bin
```

```bash
rm ~/disk-lab/file3.bin
```

Удалите пустой каталог:

```bash
rmdir ~/disk-lab
```

Проверьте:

```bash
ls ~/disk-lab
```

Должно появиться сообщение об отсутствии каталога.

# Часть 10. Диагностика нехватки оперативной памяти

В этой части не требуется искусственно доводить систему до OOM.

Необходимо научиться собирать диагностические данные.

## Шаг 1. Состояние памяти

Выполните:

```bash
free -h
```

И:

```bash
grep -E 'MemTotal|MemFree|MemAvailable|SwapTotal|SwapFree' /proc/meminfo
```

Запишите:

```text
MemTotal:
MemAvailable:
SwapTotal:
SwapFree:
```

# Шаг 2. Найти процессы, использующие больше всего RAM

Выполните:

```bash
ps -eo pid,ppid,user,comm,%mem,rss --sort=-rss | head -n 15
```

Определите три самых крупных процесса по RSS.

# Шаг 3. Проверить динамику памяти

Выполните:

```bash
pidstat -r 1 5
```

И:

```bash
vmstat 1 10
```

Обратите внимание на:

```text
free
si
so
```

# Шаг 4. Проверить OOM-события

Выполните:

```bash
sudo journalctl -k -b | grep -Ei 'out of memory|oom|killed process'
```

Если ничего не найдено, это нормальный результат.

# Шаг 5. Проверить pressure

```bash
cat /proc/pressure/memory
```

Сохраните результат.

# Подсказки по ключевым частям

## Как определить системный диск

Сначала:

```bash
findmnt /
```

Затем:

```bash
lsblk
```

Если `/` расположен на `/dev/sda2`, не использовать `/dev/sda` для LVM-практики.


```bash

```

```text
available
```

## Как проверить swap

```bash
swapon --show
```

И:


Особенно:

Конкретные процессы:

## Как понять, какой диск соответствует каталогу

Например:

```bash
df -hT /tmp
```

или:

```bash
findmnt -T /tmp
```

Для `/var`:

```bash
findmnt -T /var
```

## Как диагностировать заполнение файловой системы

Начать:

```bash
df -hT
```

Потом:

```bash
df -i
```

Затем:

```bash
sudo du -xhd1 / 2>/dev/null | sort -h
```

## Как найти большие файлы

Например в `/var`:

```bash
sudo find /var -xdev -type f -size +100M -printf '%s %p\n' 2>/dev/null | sort -nr | head -n 20
```

В домашнем учебном каталоге:

```bash
find ~/disk-lab -type f -size +50M -ls
```

## Как проверить OOM

```bash
sudo journalctl -k -b | grep -Ei 'out of memory|oom|killed process'
```

Пустой результат не является ошибкой.

Он означает, что соответствующих сообщений в выбранном журнале не обнаружено.

## Как проверить LVM

```bash

```

```bash

```

```bash
sudo lvs
```

Смысл уровней:

```text
PV
↓
VG
↓
LV
```

## Как правильно запускать stress-ng

Всегда использовать ограничение времени.

Правильно:

```bash
stress-ng --cpu 1 --timeout 30s
```

Не использовать бесконечную нагрузку без необходимости.

Для RAM в этой работе:

```bash
stress-ng --vm 1 --vm-bytes 20% --timeout 30s
```

Для диска:

```bash
stress-ng --hdd 1 --hdd-bytes 128M --temp-path /tmp --timeout 30s
```

# Советы по улучшению работы

Не ограничивайтесь скриншотом команды. Под каждым важным результатом кратко объясните, что именно видно в выводе.

Например вместо:

```text
free -h выполнено
```

лучше написать:

```text
Виртуальной машине выделено 2 ГБ RAM. На момент проверки MemAvailable составлял 1,3 ГБ. Swap размером 2 ГБ практически не использовался, поэтому признаков серьезного давления на оперативную память не наблюдалось.
```

При анализе CPU всегда сопоставляйте `load average` с количеством процессоров:

```bash
nproc
```

Значение load `2` для машины с одним CPU и машины с восемью CPU означает разную ситуацию.

При анализе памяти не ориентируйтесь только на:

```text
free
```

Смотрите:

```text
available
```

и динамику:

```text
si
so
```

через:

```bash
vmstat
```

При анализе дискового пространства сначала определяйте проблемную файловую систему:

```bash
df -hT
```

а только затем ищите данные:

```bash
du
```

Не начинайте с удаления файлов.

При ошибке:

```text
No space left on device
```

обязательно проверяйте не только гигабайты:

```bash
df -h
```

но и inode:

```bash
df -i
```

При LVM всегда проверяйте устройство несколько раз:

```bash
findmnt /
```

```bash
lsblk
```

```bash
lsblk -f
```

Ошибочно выполненный:

```bash
sudo pvcreate
```

на системном диске может привести к потере данных.

Используйте отдельный виртуальный диск VirtualBox. Для учебной практики 2–4 ГБ более чем достаточно.

При нагрузочном тестировании цель заключается не в том, чтобы «положить» Ubuntu, а в том, чтобы увидеть изменение метрик.

Поэтому лучше выполнить:

```bash
stress-ng --cpu 1 --timeout 30s
```

и внимательно сравнить показатели, чем запустить максимально возможное число workers.

Не пытайтесь специально вызвать OOM Killer.

Его диагностика изучается через:

```bash
journalctl
```

а не через намеренное исчерпание всей памяти учебной машины.

Особенно при работе через SSH следует оставлять запас ресурсов. Если виртуальная машина перестанет отвечать из-за чрезмерной нагрузки, наблюдать показатели уже не получится.

Финальная работа должна показывать не только знание отдельных команд, но и диагностическую последовательность:

```text
симптом
↓
определение проблемного ресурса
↓
измерение
↓
поиск процесса или причины
↓
проверка гипотезы
↓
вывод
```

Основной результат этой практики — умение отличить высокую загрузку CPU от нехватки RAM, активного swap, дискового I/O и нехватки места, а затем подтвердить вывод конкретными командами Linux.
