# Практическое задание: процессы в Linux

## Цель

Цель практической работы — научиться просматривать, анализировать и управлять процессами в Linux. После выполнения задания вы сможете понимать, что такое процесс, PID, родительский процесс, состояние процесса, как использовать команды `ps`, `top`, `htop`, как завершать процессы с помощью `kill`, `pkill`, `killall`, как запускать процессы в фоне, возвращать их на передний план, приостанавливать и продолжать выполнение через `jobs`, `fg`, `bg`, а также как управлять приоритетом процессов с помощью `nice` и `renice`.

В этой работе важно не просто выполнить команды, а понять, как Linux управляет запущенными программами.

## Практическое задание

Представьте, что вы администратор Linux-сервера. На сервере одновременно работают разные программы: часть запущена пользователями, часть работает в фоне, некоторые процессы потребляют ресурсы, а некоторые нужно корректно остановить.

Вам нужно научиться находить нужные процессы, смотреть их параметры, запускать процессы в фоне, управлять заданиями shell, менять приоритеты и безопасно завершать тестовые процессы.

Все действия выполняйте только с тестовыми процессами, которые вы сами создадите в ходе работы. Не завершайте системные процессы, если не понимаете, за что они отвечают.

## Задание

### Шаг 1. Посмотрите текущие процессы пользователя

Выполните команду:

```bash
ps
```

Посмотрите, какие процессы отображаются.

Затем выполните:

```bash
ps -f
```

Сравните вывод с обычной командой `ps`.

Теперь выполните:

```bash
ps aux
```

Эта команда покажет намного больше процессов, включая процессы других пользователей и системные процессы.

Найдите в выводе такие столбцы:

```text
USER
PID
%CPU
%MEM
STAT
START
TIME
COMMAND
```

Запишите, что означает каждый из этих столбцов.

### Шаг 2. Найдите процесс текущего shell

Узнайте PID текущего shell:

```bash
echo $$
```

Теперь найдите этот процесс через `ps`:

```bash
ps -p $$
```

Выведите подробную информацию:

```bash
ps -fp $$
```

Посмотрите, какая команда запустила ваш текущий shell.

### Шаг 3. Посмотрите дерево процессов

Выполните команду:

```bash
ps -ef
```

Обратите внимание на столбцы `PID` и `PPID`.

Теперь выполните:

```bash
ps -ef | head
```

Если в системе есть команда `pstree`, выполните:

```bash
pstree
```

Если `pstree` не установлена, этот шаг можно выполнить только через `ps -ef`.

Ответьте на вопросы:

```text
Что такое PID?
Что такое PPID?
Почему у процесса может быть родительский процесс?
Какой процесс обычно является родителем для команд, запущенных из терминала?
```

### Шаг 4. Найдите процессы по имени

Найдите процессы, связанные с вашим shell:

```bash
ps aux | grep bash
```

Если вы используете другой shell, например `zsh`, выполните:

```bash
ps aux | grep zsh
```

Обратите внимание, что в вывод может попасть и сам процесс `grep`.

Более удобный вариант поиска:

```bash
pgrep bash
```

Или с отображением имени процесса:

```bash
pgrep -a bash
```

Если `pgrep` не установлен, используйте поиск через `ps aux | grep`.

### Шаг 5. Запустите тестовый процесс

Запустите процесс, который будет работать 300 секунд:

```bash
sleep 300
```

Пока процесс работает, терминал будет занят. Это пример интерактивного процесса, запущенного на переднем плане.

Остановите его сочетанием клавиш:

```text
Ctrl + C
```

После этого процесс должен завершиться.

Теперь снова запустите:

```bash
sleep 300
```

Но на этот раз не завершайте его через `Ctrl + C`.

### Шаг 6. Приостановите процесс и посмотрите задания shell

Когда `sleep 300` работает на переднем плане, нажмите:

```text
Ctrl + Z
```

Процесс будет приостановлен, а управление вернётся в терминал.

Посмотрите список заданий текущего shell:

```bash
jobs
```

Вы должны увидеть приостановленное задание примерно такого вида:

```text
[1]+  Stopped  sleep 300
```

Теперь посмотрите процессы:

```bash
ps
```

Или подробнее:

```bash
ps -f
```

### Шаг 7. Продолжите процесс в фоне

Продолжите приостановленное задание в фоне:

```bash
bg
```

Проверьте список заданий:

```bash
jobs
```

Теперь процесс должен иметь состояние `Running`.

Проверьте его через `ps`:

```bash
ps -f
```

### Шаг 8. Верните фоновый процесс на передний план

Верните задание на передний план:

```bash
fg
```

Терминал снова будет занят процессом `sleep`.

Завершите процесс через:

```text
Ctrl + C
```

Проверьте, что заданий больше нет:

```bash
jobs
```

### Шаг 9. Запустите процесс сразу в фоне

Запустите процесс в фоне с помощью символа `&`:

```bash
sleep 500 &
```

Shell должен вывести номер задания и PID процесса, например:

```text
[1] 12345
```

Проверьте задания:

```bash
jobs
```

Проверьте процесс по PID. Вместо `12345` подставьте PID, который появился у вас:

```bash
ps -p 12345
```

Или найдите процесс так:

```bash
pgrep -a sleep
```

### Шаг 10. Завершите процесс через kill

Найдите PID процесса `sleep`:

```bash
pgrep -a sleep
```

Завершите процесс командой `kill`.

Пример:

```bash
kill 12345
```

Где `12345` — PID вашего процесса.

Проверьте, что процесс завершён:

```bash
pgrep -a sleep
jobs
```

Если процесс не завершился, можно использовать более жёсткий сигнал:

```bash
kill -9 12345
```

Но `kill -9` используйте только для тестовых процессов и только если обычный `kill` не помог.

### Шаг 11. Завершите процессы через pkill

Запустите несколько тестовых процессов:

```bash

sleep 600 &
sleep 600 &
```

Проверьте:

```bash
pgrep -a sleep
```

Завершите все процессы с именем `sleep`:

```bash
pkill sleep
```

Проверьте:

```bash
pgrep -a sleep
jobs
```

Если задания отображаются как завершённые, нажмите Enter или снова выполните `jobs`.

### Шаг 12. Завершите процессы через killall

Запустите ещё несколько процессов:

```bash
sleep 700 &
sleep 700 &
```

Проверьте:

```bash
pgrep -a sleep
```

Завершите их командой:

```bash
killall sleep
```

Проверьте:

```bash
pgrep -a sleep
jobs
```

Если команда `killall` не установлена, этот шаг можно пропустить или выполнить через `pkill sleep`.

### Шаг 13. Сравните kill, pkill и killall

В отчёте кратко объясните разницу:

```text
kill завершает процесс по PID.
pkill завершает процесс по имени или шаблону.
killall завершает процессы по точному имени команды.
```

Дополнительно ответьте:

```text

```

```text

SIGKILL
SIGSTOP

```

## Подсказки по ключевым частям

Процесс в Linux — это запущенная программа. Когда вы запускаете команду в терминале, Linux создаёт для неё процесс. Например, если выполнить команду `sleep 300`, система создаст процесс, который ничего не делает 300 секунд, а потом завершится.

У каждого процесса есть PID — Process ID. Это уникальный номер процесса в системе. PID нужен для того, чтобы можно было обратиться к конкретному процессу. Например, если вы хотите завершить процесс, вы обычно отправляете сигнал именно по PID.

Кроме PID у процесса есть PPID — Parent Process ID. Это PID родительского процесса. Родительский процесс — это процесс, который запустил другой процесс. Например, когда вы запускаете команду из терминала, родительским процессом обычно является ваш shell: `bash`, `zsh` или другой командный интерпретатор.

Команда `ps` показывает процессы. В простом варианте:

```bash
ps
```

она показывает только процессы, связанные с текущим терминалом. Поэтому вывод может быть коротким.

Команда:

```bash
ps -f
```

показывает более подробную информацию, включая UID, PID, PPID, время запуска и команду.

Команда:

```bash
ps aux
```

показывает процессы всех пользователей в BSD-стиле вывода. Это один из самых популярных вариантов команды `ps`, потому что он позволяет увидеть почти всё, что сейчас запущено в системе.

В выводе `ps aux` столбец `USER` показывает пользователя, от имени которого запущен процесс. Столбец `PID` показывает идентификатор процесса. `%CPU` показывает примерную долю использования процессора. `%MEM` показывает использование оперативной памяти. `STAT` показывает состояние процесса. `COMMAND` показывает команду, которой процесс был запущен.

Состояния процессов могут быть разными. Например, `R` означает running — процесс выполняется или готов выполняться. `S` означает sleeping — процесс ожидает событие. `T` означает stopped — процесс остановлен, например через `Ctrl + Z` или сигнал `SIGSTOP`. `Z` означает zombie — процесс завершился, но его родитель ещё не забрал код завершения.

Команда `top` показывает процессы в интерактивном режиме. В отличие от `ps`, она постоянно обновляет информацию. Через `top` удобно смотреть, какие процессы используют больше всего CPU или памяти. Внутри `top` можно сортировать процессы, завершать их, менять nice и просматривать общую нагрузку на систему.

Команда `htop` похожа на `top`, но обычно удобнее визуально. Она показывает цветной интерфейс, позволяет искать процессы, сортировать их, отправлять сигналы и смотреть дерево процессов. Но `htop` может быть не установлен по умолчанию, поэтому иногда его нужно установить отдельно.

Команда `kill` не обязательно «убивает» процесс сразу. На самом деле она отправляет процессу сигнал. По умолчанию `kill PID` отправляет сигнал `SIGTERM`. Это просьба корректно завершиться. Процесс может обработать этот сигнал, закрыть файлы, сохранить данные и завершиться.

Сигнал `SIGKILL`, который часто отправляют как `kill -9 PID`, завершает процесс принудительно. Процесс не может его перехватить или проигнорировать. Поэтому `kill -9` нужно использовать осторожно. Он полезен, когда процесс завис и не реагирует на обычное завершение, но при этом программа может не успеть сохранить данные.

Команда `pkill` завершает процессы по имени или шаблону. Например:

```bash
pkill sleep
```

завершит процессы, имя которых подходит под `sleep`.

Команда `killall` тоже завершает процессы по имени команды. Например:

```bash
killall sleep
```

завершит все процессы `sleep`. Разница между `pkill` и `killall` зависит от системы и реализации, но в обычной практике обе команды требуют осторожности, потому что можно завершить больше процессов, чем планировалось.

Фоновые процессы запускаются с помощью символа `&`. Например:

```bash
sleep 300 &
```

В этом случае команда запускается, но терминал сразу возвращает управление пользователю. Shell показывает номер задания и PID процесса.

Задание shell — это процесс или группа процессов, которыми управляет текущий shell. Команда `jobs` показывает задания текущего shell. Важно понимать, что `jobs` показывает не все процессы системы, а только те задания, которые были запущены именно из текущего shell и ещё связаны с ним.

Команда `fg` возвращает фоновое или остановленное задание на передний план. Например:

```bash
fg
```

Если заданий несколько, можно указать номер:

```bash
fg %1
```

Команда `bg` продолжает остановленное задание в фоне:

```bash
bg
```

Если заданий несколько:

```bash
bg %1
```

Сочетание клавиш `Ctrl + C` отправляет процессу на переднем плане сигнал прерывания, обычно `SIGINT`. Чаще всего это завершает процесс.

Сочетание `Ctrl + Z` не завершает процесс, а приостанавливает его. После этого процесс остаётся в системе, но не выполняется. Его можно продолжить через `fg`, `bg` или сигнал `SIGCONT`.

Команда `nice` задаёт приоритет процессу при запуске. В Linux nice обычно находится в диапазоне от `-20` до `19`. Чем меньше значение nice, тем выше приоритет процесса. Чем больше значение nice, тем процесс «вежливее» к другим процессам и тем ниже его приоритет.

Например:

```bash
nice -n 10 sleep 300
```

запускает процесс с пониженным приоритетом.

Обычный пользователь обычно может только увеличивать nice, то есть понижать приоритет своих процессов. Чтобы поставить отрицательное значение nice и повысить приоритет, обычно нужны права администратора.

Команда `renice` меняет nice уже запущенного процесса:

```bash
renice 15 -p 12345
```

Это изменит nice процесса с PID `12345`.

Команда `nohup` запускает процесс так, чтобы он не завершался при закрытии терминала. Название означает no hangup. Обычно вывод такой команды перенаправляется в файл `nohup.out`, если явно не указать другой файл.

Команда `disown` отвязывает задание от текущего shell. После этого оно больше не отображается через `jobs`, но сам процесс может продолжать работать. Это полезно, если вы запустили процесс в фоне и не хотите, чтобы shell управлял им как заданием.

Важно отличать процессы и задания shell. Процесс — это объект операционной системы. Его можно увидеть через `ps`, `top`, `htop`, `pgrep`. Задание — это объект управления внутри текущего shell. Его можно увидеть через `jobs`. Поэтому процесс может существовать, но не отображаться в `jobs`, особенно если он был запущен не из текущего shell или был отвязан через `disown`.

## Что проверить перед отправкой

Перед отправкой работы проверьте, что вы умеете просматривать процессы:

```bash
ps
ps -f
ps aux
```

Проверьте, что вы знаете PID текущего shell:

```bash
echo $$
ps -fp $$
```

Проверьте, что вы умеете запускать процесс в фоне:

```bash
sleep 300 &
jobs
```

Проверьте, что вы умеете приостанавливать и продолжать процесс:

```text
Ctrl + Z
jobs
bg
fg
```

Проверьте, что вы умеете находить процесс по имени:

```bash
pgrep -a sleep
```

Проверьте, что вы умеете завершать процесс по PID:

```bash
kill PID
```

Проверьте, что вы умеете завершать процессы по имени:

```bash
pkill sleep
killall sleep
```

Проверьте, что вы умеете смотреть процессы в `top`:

```bash
top
```

Проверьте, что вы умеете смотреть процессы в `htop`, если он установлен:

```bash
htop
```

Проверьте, что вы умеете запускать процесс с nice:

```bash
nice -n 10 sleep 300 &
ps -o pid,ni,cmd -p PID
```

Проверьте, что вы умеете менять nice через `renice`:

```bash
renice 15 -p PID
ps -o pid,ni,cmd -p PID
```

Проверьте, что после работы не осталось тестовых процессов:

```bash
pgrep -a sleep
pgrep -a yes
```

Если процессы остались, завершите их:

```bash
pkill sleep
pkill yes
```

В отчёте нужно показать команды и выводы проверок. Особенно важно показать:

```text
вывод ps;
PID текущего shell;
запуск sleep в фоне;
вывод jobs;
пример fg и bg;
завершение процесса через kill;
завершение процессов через pkill или killall;
просмотр процесса в top или htop;
пример nice;
пример renice;
финальную проверку, что тестовые процессы завершены.
```

## Советы по улучшению работы

Используйте только тестовые процессы, которые вы сами запустили. Самые безопасные варианты для практики — `sleep` и `yes > /dev/null`. Процесс `sleep` почти не использует ресурсы, поэтому подходит для тренировки `jobs`, `fg`, `bg`, `kill`, `pkill` и `killall`. Процесс `yes > /dev/null` активно использует CPU, поэтому подходит для просмотра нагрузки в `top` или `htop`, но его обязательно нужно завершить после проверки.

Не используйте `kill -9` как первый вариант. Сначала попробуйте обычный `kill PID`, который отправляет `SIGTERM`. Принудительный сигнал `SIGKILL` используйте только тогда, когда процесс не реагирует.

Будьте осторожны с `pkill` и `killall`. Если указать слишком общее имя, можно завершить лишние процессы. Например, в реальной системе нельзя бездумно выполнять команды вроде `pkill python`, потому что под этим именем могут работать важные приложения или сервисы.

Когда работаете с `jobs`, помните, что задания привязаны к текущему shell. Если открыть другой терминал и выполнить `jobs`, вы не увидите задания, запущенные в первом терминале. Но через `ps`, `top` или `pgrep` процессы всё равно можно найти.

Не путайте `Ctrl + C` и `Ctrl + Z`. `Ctrl + C` обычно завершает процесс, а `Ctrl + Z` только приостанавливает его. После `Ctrl + Z` процесс остаётся в системе, поэтому его нужно либо продолжить через `fg` или `bg`, либо завершить через `kill`.

Если команда `htop` не установлена, не считайте это ошибкой выполнения задания. Основной инструмент Linux для просмотра процессов — это `ps` и `top`. `htop` является удобным дополнительным инструментом.

Для отчёта можно сохранить часть результатов в файл:

```bash
echo "=== Current shell PID ===" >> process_report.txt
echo $$ >> process_report.txt

echo "=== ps -f ===" >> process_report.txt
ps -f >> process_report.txt

echo "=== ps aux head ===" >> process_report.txt
ps aux | head >> process_report.txt

echo "=== sleep processes ===" >> process_report.txt
pgrep -a sleep >> process_report.txt

echo "=== nice example ===" >> process_report.txt
ps -o pid,ni,cmd -p PID >> process_report.txt
```

Вместо `PID` нужно подставить реальный PID процесса.

Главный результат этой практической работы — понимание жизненного цикла процесса: запуск, просмотр, приостановка, перевод в фон, возврат на передний план, изменение приоритета и завершение.
