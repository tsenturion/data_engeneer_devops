# Практическое задание

## Цель

Научиться использовать Bash как интерактивную командную оболочку и как язык автоматизации. В ходе работы необходимо исследовать текущую оболочку Ubuntu, настроить пользовательское окружение, создать несколько небольших Bash-скриптов и объединить изученные конструкции в итоговую программу формирования системного отчёта.

В результате работы вы должны продемонстрировать понимание различий между терминалом и shell, интерактивным и неинтерактивным режимами, переменными оболочки и переменными окружения, а также научиться использовать аргументы командной строки, стандартные потоки, коды возврата, перенаправления и конвейеры.

Все файлы практической работы размещайте в отдельной директории:

```bash
mkdir -p ~/bash-practice
cd ~/bash-practice
```

### Шаг 23. Создайте итоговый скрипт системного отчёта

Создайте файл:

```bash
nano system-report.sh
```

Скрипт должен принимать необязательный первый аргумент — имя итогового файла. Если аргумент не передан, должно использоваться имя:

```text
system-report.txt
```

Скрипт должен содержать:

```bash
#!/usr/bin/env bash
```

В начале включите:

```bash
set -o pipefail
```

В отчёт необходимо записать:

```text
дату и время;
имя сервера;
имя пользователя;
текущую оболочку;
версию Bash;
текущий каталог;
IP-адреса;
маршрут по умолчанию;
использование дисков;
использование памяти;
количество пользователей в /etc/passwd;
пять наиболее часто используемых пользовательских оболочек;
список слушающих TCP-портов.
```

Используйте переменные:

```bash
output_file="${1:-system-report.txt}"
current_date=$(date '+%Y-%m-%d %H:%M:%S')
server_name=$(hostname)
current_user=$(whoami)
```

Весь отчёт направьте в один файл через групповое перенаправление:


При ошибке выведите сообщение в `stderr` и завершите скрипт с ненулевым кодом.

```bash
chmod +x system-report.sh
```

## Подсказки по ключевым частям

Переменные объявляются без пробелов вокруг знака `=`:

```bash
name="Иван"
```

При использовании переменных почти всегда ставьте двойные кавычки:

```bash
echo "$name"
rm "$file_name"
```

Используйте форму:

```bash
"${variable}"
```

если рядом с именем переменной находятся буквы, цифры или подчёркивание:

```bash
echo "${name}_report.txt"
```

Для аргументов используйте:

```bash
"$@"
```

Эта форма сохраняет каждый аргумент отдельно, включая аргументы с пробелами.

Не используйте `"$*"` для передачи аргументов другой команде, если каждый аргумент должен остаться отдельным.

Значение `$?` сохраняйте сразу:

```bash
command
status=$?
```

Но по возможности используйте команду прямо в условии:

```bash
if command; then
    echo "Успешно"
else
    echo "Ошибка"
fi
```

Для сообщений об ошибках используйте `stderr`:

```bash
echo "Ошибка" >&2
```

Для успешного завершения:

```bash
exit 0
```

Для ошибки:

```bash
exit 1
```

Для ошибки использования аргументов:

```bash
exit 2
```

Для подстановки команд используйте:

```bash
result=$(command)
```

Не используйте устаревшие обратные кавычки:

```bash
result=`command`
```

При создании файлов через here-document заключите маркер в кавычки, если не хотите раскрывать переменные:

```bash
cat <<'EOF'
$USER
EOF
```

Для надёжной обработки конвейеров включайте:

```bash
set -o pipefail
```

Перед прямым запуском файла проверьте:

```bash
head -n 1 script.sh
ls -l script.sh
```

В первой строке должен быть shebang, а в правах должен присутствовать `x`.

Если после изменения `.bashrc` новые настройки не появились, выполните:

```bash
source ~/.bashrc
```

Если `.bashrc` перестал корректно загружаться, восстановите резервную копию:

```bash
cp ~/.bashrc.backup ~/.bashrc
source ~/.bashrc
```

## Советы по улучшению работы

Не ограничивайтесь успешным выполнением скриптов. Покажите хотя бы несколько ошибочных сценариев: запуск без обязательных аргументов, обращение к несуществующему файлу и попытку записать отчёт в недоступный каталог. Для каждого сценария сохраните код возврата и объясните его.

Добавьте в итоговый скрипт цветной вывод, но используйте цвета только в терминале. Проверить вывод в терминал можно так:

```bash
if [[ -t 1 ]]; then
    green='\033[32m'
    red='\033[31m'
    reset='\033[0m'
else
    green=''
    red=''
    reset=''
fi
```

Добавьте функцию вывода сообщений:

```bash
log_info() {
    printf '[INFO] %s\n' "$1"
}

log_error() {
    printf '[ERROR] %s\n' "$1" >&2
}
```

Добавьте функцию проверки наличия команды:

```bash
require_command() {
    if ! command -v "$1" > /dev/null 2>&1; then
        printf 'Не найдена команда: %s\n' "$1" >&2
        return 1
    fi
}
```

Перед созданием отчёта проверьте необходимые программы:

```bash
require_command ip || exit 1
require_command ss || exit 1
require_command df || exit 1
```

Добавьте защиту от случайной перезаписи существующего файла:

```bash
if [[ -e "$output_file" ]]; then
    printf 'Файл уже существует: %s\n' "$output_file" >&2
    exit 1
fi
```

Или создавайте имя с датой:

```bash
output_file="system-report-$(date +%Y-%m-%d_%H-%M-%S).txt"
```

Добавьте продолжительность выполнения:

```bash
start_time=$SECONDS

# Основной код

duration=$((SECONDS - start_time))
printf 'Время выполнения: %d секунд\n' "$duration"
```

Добавьте собственную справку:

```bash
show_help() {
    cat <<'EOF'
Использование:
  ./system-report.sh [имя_файла]

Если имя файла не указано, используется system-report.txt.
EOF
}
```

Обрабатывайте параметр:

```bash
if [[ ${1:-} == "--help" || ${1:-} == "-h" ]]; then
    show_help
    exit 0
fi
```

Не добавляйте сложность только ради количества строк. Улучшения должны повышать надёжность, понятность или удобство использования программы.
