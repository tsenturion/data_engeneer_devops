# Практическое задание. Работа с дисками, файловыми системами и USB-накопителями в Linux

## Цель

Научиться определять подключенные диски и разделы в Ubuntu, анализировать их файловые системы и свободное пространство, подключать и отключать файловые системы вручную, работать с USB-накопителем, определять UUID устройства, настраивать права доступа к смонтированной файловой системе и понимать назначение файла `/etc/fstab`.

В ходе работы необходимо закрепить использование команд:

```bash
lsblk
df
du
blkid
findmnt
mount
umount
chown
chmod
id
```

Основной вариант практики выполняется с USB-накопителем.

Если USB-накопителя нет или его невозможно передать внутрь виртуальной машины, необходимо выполнить альтернативный вариант с дополнительным виртуальным диском VirtualBox.

Не выполняйте форматирование, изменение разделов или другие потенциально разрушительные операции над системным диском Ubuntu.

# Задание

## Часть 1. Проверка текущей Ubuntu

Перед подключением любого дополнительного устройства необходимо определить текущую конфигурацию системы.

### Шаг 1. Определите пользователя и компьютер

Выполните:

```bash
hostname
```

Затем:

```bash
whoami
```

Получите подробную информацию о текущем пользователе:

```bash
id
```

Запишите:

```text
имя виртуальной машины;
имя пользователя;
UID пользователя;
GID основной группы.
```

Если работа выполняется по SSH, дополнительно можно проверить информацию о текущем подключении:

```bash
who
```

## Шаг 2. Посмотрите существующие диски

Выполните:

```bash
lsblk
```

Затем:

```bash
lsblk -f
```

После этого используйте более подробный вариант:

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,LABEL,UUID,MOUNTPOINTS
```

Если необходимо определить, является ли устройство USB-устройством:

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,LABEL,TRAN,MOUNTPOINTS
```

Сохраните вывод этих команд.

Определите системный диск.

Для этого выполните:

```bash
findmnt /
```

Например, если результат показывает:

```text
/    /dev/sda2
```

значит корневая файловая система находится на `/dev/sda2`, а `/dev/sda` является системным диском.

Системный диск в дальнейших экспериментах использовать нельзя.

# Часть 2. Проверка свободного пространства

Выполните:

```bash
df -h
```

Затем:

```bash
df -hT
```

Определите:

```text
общий размер корневой файловой системы;
использованное пространство;
доступное пространство;
процент заполнения;
тип файловой системы.
```

Отдельно проверьте корневую файловую систему:

```bash
df -hT /
```

Проверьте домашний каталог:

```bash
df -hT ~
```

# Часть 3. Анализ занимаемого пространства через `du`

Определите общий размер своей домашней директории:

```bash
du -sh ~
```

Посмотрите размеры каталогов первого уровня:

```bash
du -h --max-depth=1 ~
```

Отсортируйте их по размеру:

```bash
du -h --max-depth=1 ~ | sort -hr
```

Определите три самых крупных каталога в своей домашней директории.

Если появляются сообщения:

```text
Permission denied
```

это не обязательно означает ошибку команды. Для системных каталогов могут потребоваться повышенные права.

Например:

```bash
sudo du -h --max-depth=1 /var 2>/dev/null | sort -hr
```

Далее необходимо выбрать один из двух сценариев.

Есть USB-флешка, которую можно подключить к Ubuntu.

Используйте ее.

### Сценарий B

# Сценарий A. Работа с USB-флешкой

## Шаг 1. Подключение флешки

Если Ubuntu установлена непосредственно на физический компьютер, подключите USB-флешку обычным способом.

Если Ubuntu работает в VirtualBox, необходимо передать USB-устройство виртуальной машине.

Флешка, подключенная к основному компьютеру, не становится автоматически доступной внутри виртуальной Ubuntu.

В VirtualBox USB-устройство необходимо подключить именно к виртуальной машине.

После подключения флешки не выполняйте никаких операций форматирования.

## Шаг 2. Определите новое устройство

До подключения USB желательно выполнить:

```bash
lsblk
```

После подключения повторите:

```bash
lsblk
```

Затем:

```bash
lsblk -f
```

И:

```bash
lsblk -o NAME,MODEL,SIZE,TYPE,FSTYPE,LABEL,TRAN,MOUNTPOINTS
```

Найдите устройство, у которого:

```text
TRAN = usb
```

Например результат может выглядеть так:

```text
sda      30G disk
├─sda1    1G part ext4
└─sda2   29G part ext4      /

sdb      32G disk                 usb
└─sdb1   32G part exfat MY_USB
```

В данном примере:

```text
/dev/sda
```

является системным диском.

А:

```text
/dev/sdb
```

является USB-накопителем.

Работать необходимо с разделом:

```text
/dev/sdb1
```

У вас название устройства может отличаться.

Не копируйте `/dev/sdb1` механически из примера.

Определите устройство через `lsblk`.

# Шаг 3. Определите файловую систему флешки

Выполните:

```bash
lsblk -f
```

Затем:

```bash
sudo blkid
```

Или только для найденного раздела:

```bash
sudo blkid /dev/sdb1
```

Замените `/dev/sdb1` на свое устройство.

Определите:

```text
тип файловой системы;
UUID;
LABEL, если метка присутствует.
```

На флешке может использоваться:

```text
vfat
exfat
ntfs
ext4
```

# Если команда `blkid` отсутствует

На стандартной Ubuntu она обычно уже установлена в составе `util-linux`.

Если команда по какой-либо причине отсутствует:

```bash
sudo apt update
```

```bash
sudo apt install util-linux
```

После установки:

```bash
sudo blkid
```

# Шаг 4. При необходимости установите поддержку файловой системы

Для обычного `ext4` дополнительная установка не требуется.

Для работы с инструментами exFAT можно установить:

```bash
sudo apt update
```

```bash
sudo apt install exfatprogs
```

Для дополнительной совместимости с NTFS можно установить:

```bash
sudo apt update
```

```bash
sudo apt install ntfs-3g
```

Не устанавливайте эти пакеты без необходимости. Сначала определите файловую систему через:

```bash
lsblk -f
```

# Шаг 5. Проверьте, не смонтировалась ли флешка автоматически

Выполните:

```bash
lsblk -f
```

Посмотрите колонку:

```text
MOUNTPOINTS
```

Затем:

```bash
findmnt
```

Если рядом с USB-разделом уже указан путь, например:

```text
/media/student/MY_USB
```

или:

```text
/run/media/student/MY_USB
```

значит система уже смонтировала накопитель.

В этом случае зафиксируйте текущую точку монтирования.

Для дальнейшей ручной практики накопитель можно размонтировать.

Перед этим выйдите из каталога флешки:

```bash
cd ~
```

После этого:

```bash
sudo umount /dev/sdb1
```

Замените устройство на свое.

Проверьте:

```bash
lsblk -f
```

Точка монтирования должна исчезнуть.

# Шаг 6. Создайте собственную точку монтирования

Создайте каталог:

```bash
sudo mkdir -p /mnt/usb
```

Проверьте:

```bash
ls -ld /mnt/usb
```

# Шаг 7. Смонтируйте USB-накопитель

Если используется `ext4`, можно выполнить:

```bash
sudo mount /dev/sdb1 /mnt/usb
```

Если используется exFAT и обычное монтирование работает:

```bash
sudo mount /dev/sdb1 /mnt/usb
```

После этого обязательно проверьте результат:

```bash
findmnt /mnt/usb
```

Также:

```bash
lsblk -f
```

И:

```bash
df -hT /mnt/usb
```

Необходимо определить:

```text
какое устройство смонтировано;
тип файловой системы;
размер;
сколько пространства занято;
сколько пространства свободно.
```

# Шаг 8. Посмотрите содержимое накопителя

Выполните:

```bash
ls -lah /mnt/usb
```

Не удаляйте существующие пользовательские файлы.

# Шаг 9. Проверьте права

Посмотрите права точки монтирования:

```bash
ls -ld /mnt/usb
```

Узнайте своего пользователя:

```bash
whoami
```

Узнайте UID:

```bash
id -u
```

Узнайте GID:

```bash
id -g
```

Попробуйте создать учебный каталог:

```bash
mkdir /mnt/usb/linux-practice
```

Если каталог создался, перейдите к следующему этапу.

Если получили:

```text
Permission denied
```

сначала определите тип файловой системы.

# Шаг 10. Если флешка использует `ext4`

Для `ext4` можно использовать стандартные владельцы Linux.

Посмотрите:

```bash
ls -ld /mnt/usb
```

Если по условиям учебной работы весь накопитель можно передать текущему пользователю, выполните:

```bash
sudo chown "$(whoami)":"$(id -gn)" /mnt/usb
```

Проверьте:

```bash
ls -ld /mnt/usb
```

После этого:

```bash
mkdir /mnt/usb/linux-practice
```

# Шаг 11. Если используется exFAT или FAT

Для файловых систем вроде exFAT классические Unix-владельцы работают иначе.

Сначала размонтируйте флешку:

```bash
cd ~
```

```bash
sudo umount /mnt/usb
```

Узнайте UID:

```bash
id -u
```

Узнайте GID:

```bash
id -g
```

Например оба значения равны:

```text
1000
```

Тогда можно выполнить:

```bash
sudo mount -o uid=1000,gid=1000,umask=022 /dev/sdb1 /mnt/usb
```

Значения `1000` замените на реальные значения из:

```bash
id -u
```

и:

```bash
id -g
```

После этого:

```bash
ls -ld /mnt/usb
```

И:

```bash
mkdir /mnt/usb/linux-practice
```

# Шаг 12. Создайте тестовые данные

Создайте каталог:

```bash
mkdir -p /mnt/usb/linux-practice
```

Создайте файл:

```bash
touch /mnt/usb/linux-practice/test.txt
```

Запишите в него информацию:

```bash
echo "Практическая работа Linux" > /mnt/usb/linux-practice/test.txt
```

Добавьте имя текущего пользователя:

```bash
whoami >> /mnt/usb/linux-practice/test.txt
```

Добавьте имя хоста:

```bash
hostname >> /mnt/usb/linux-practice/test.txt
```

Посмотрите содержимое:

```bash
cat /mnt/usb/linux-practice/test.txt
```

Посмотрите информацию о файле:

```bash
ls -l /mnt/usb/linux-practice/test.txt
```

# Шаг 13. Определите объем созданного каталога

Выполните:

```bash
du -sh /mnt/usb/linux-practice
```

Затем:

```bash
df -hT /mnt/usb
```

Обратите внимание на разницу:

`du` показывает размер файлов и каталогов.

`df` показывает состояние файловой системы целиком.

# Шаг 14. Получите UUID накопителя

Выполните:

```bash
sudo blkid /dev/sdb1
```

Замените устройство своим.

Сохраните UUID.

Пример:

```text
UUID="18AF-2031"
```

# Шаг 15. Изучите `/etc/fstab`

Посмотрите:

```bash
cat /etc/fstab
```

Найдите записи для системных файловых систем.

Не удаляйте и не изменяйте существующие строки.

Создайте резервную копию:

```bash
sudo cp /etc/fstab /etc/fstab.backup
```

Проверьте:

```bash
ls -l /etc/fstab*
```

# Шаг 16. Составьте запись для флешки

Необязательно делать съемную флешку постоянным диском сервера.

Но необходимо самостоятельно составить корректный пример записи `/etc/fstab`.

Для ext4 он может выглядеть так:

```text
UUID=ВАШ_UUID /mnt/usb ext4 defaults,nofail 0 2
```

Для exFAT:

```text
UUID=ВАШ_UUID /mnt/usb exfat defaults,nofail,uid=1000,gid=1000,umask=022 0 0
```

Значения UUID, UID и GID должны быть вашими.

Запись необходимо сохранить в отчет.

Добавлять ее в реальный `/etc/fstab` для съемной флешки необязательно.

Если преподавателем отдельно разрешено добавить запись в `/etc/fstab`, сначала создайте резервную копию и обязательно выполните проверку.

# Шаг 17. Проверка `/etc/fstab`

Команда:

```bash
sudo findmnt --verify
```

обычно доступна в составе `util-linux`.

Если отсутствует:

```bash
sudo apt update
```

```bash
sudo apt install util-linux
```

После изменения `/etc/fstab` обязательно:

```bash
sudo findmnt --verify
```

Не перезагружайте виртуальную машину для первичной проверки.

# Шаг 18. Безопасно размонтируйте флешку

Перейдите в домашний каталог:

```bash
cd ~
```

Можно выполнить:

```bash
sync
```

Затем:

```bash
sudo umount /mnt/usb
```

Проверьте:

```bash
findmnt /mnt/usb
```

И:

```bash
lsblk -f
```

У `/dev/sdb1` больше не должно быть `/mnt/usb`.

Только после успешного размонтирования USB-накопитель можно отключать от виртуальной машины или физического компьютера.

# Если возникает ошибка `target is busy`

Если:

```bash
sudo umount /mnt/usb
```

возвращает:

```text
target is busy
```

сначала убедитесь, что терминал не находится внутри `/mnt/usb`.

Выполните:

```bash
pwd
```

Если вы находитесь внутри накопителя:

```bash
cd ~
```

Попробуйте снова:

```bash
sudo umount /mnt/usb
```

Если ошибка сохраняется, можно использовать `lsof`.

Установка:

```bash
sudo apt update
```

```bash
sudo apt install lsof
```

После установки:

```bash
sudo lsof /mnt/usb
```

Также можно использовать:

```bash
sudo fuser -vm /mnt/usb
```

Команда `fuser` обычно входит в пакет `psmisc`.

Если ее нет:

```bash
sudo apt update
```

```bash
sudo apt install psmisc
```

После установки:

```bash
sudo fuser -vm /mnt/usb
```

Не завершайте найденные процессы без понимания того, что они делают.

# Сценарий B. Если флешки нет

Если USB-накопителя нет или VirtualBox не позволяет его подключить, работа выполняется с дополнительным виртуальным диском.

Это полноценная альтернатива.

# Шаг 1. Добавьте дополнительный виртуальный диск

Полностью выключите виртуальную Ubuntu перед изменением конфигурации виртуального оборудования, если этого требует ваша конфигурация VirtualBox.

В настройках виртуальной машины добавьте отдельный виртуальный диск.

Рекомендуемый размер:

```text
2–5 ГБ
```

Не увеличивайте и не заменяйте существующий системный диск.

Не используйте существующий диск Ubuntu для практики.

После добавления диска запустите виртуальную машину и снова подключитесь по SSH.

# Шаг 2. Определите новый диск

До добавления диска желательно сохранить:

```bash
lsblk
```

После добавления:

```bash
lsblk
```

Например раньше:

```text
sda      30G disk
├─sda1    1G part /boot
└─sda2   29G part /
```

После добавления:

```text
sda      30G disk
├─sda1    1G part /boot
└─sda2   29G part /

sdb       4G disk
```

Проверьте:

```bash
lsblk -o NAME,MODEL,SIZE,TYPE,FSTYPE,MOUNTPOINTS
```

Определите новый учебный диск.

# Важно

Если новый диск выглядит так:

```text
/dev/sdb
```

но внутри него нет:

```text
/dev/sdb1
```

значит на нем пока нет раздела.

Если раздел уже существует, можно продолжить работу с ним.

Если раздела нет, создание разделов будет относиться уже к следующей теме курса.

Для текущей практики преподаватель может предоставить заранее подготовленный виртуальный диск с разделом и файловой системой.

# Альтернативный вариант без создания раздела вручную

Если дополнительный диск уже подготовлен и имеет, например:

```text
/dev/sdb1
```

выполните:

```bash
lsblk -f
```

Затем:

```bash
sudo blkid /dev/sdb1
```

Создайте точку монтирования:

```bash
sudo mkdir -p /mnt/data
```

Смонтируйте:

```bash
sudo mount /dev/sdb1 /mnt/data
```

Проверьте:

```bash
findmnt /mnt/data
```

```bash
df -hT /mnt/data
```

```bash
ls -ld /mnt/data
```

Если используется `ext4` и необходимо предоставить текущему пользователю доступ:

```bash
sudo chown "$(whoami)":"$(id -gn)" /mnt/data
```

После этого:

```bash
mkdir -p /mnt/data/linux-practice
```

```bash
touch /mnt/data/linux-practice/test.txt
```

```bash
echo "Учебный виртуальный диск" > /mnt/data/linux-practice/test.txt
```

```bash
hostname >> /mnt/data/linux-practice/test.txt
```

```bash
whoami >> /mnt/data/linux-practice/test.txt
```

Проверка:

```bash
cat /mnt/data/linux-practice/test.txt
```

# Шаг 3. Проверьте использование диска

Выполните:

```bash
df -hT /mnt/data
```

И:

```bash
du -sh /mnt/data
```

Сравните назначение команд.

# Шаг 4. Получите UUID

Выполните:

```bash
sudo blkid /dev/sdb1
```

Сохраните UUID.

# Шаг 5. Подготовьте постоянное монтирование

Создайте резервную копию:

```bash
sudo cp /etc/fstab /etc/fstab.backup
```

Посмотрите текущий файл:

```bash
cat /etc/fstab
```

Для учебного ext4-диска запись может выглядеть:

```text
UUID=ВАШ_UUID /mnt/data ext4 defaults,nofail 0 2
```

Если задание выполняется на собственной учебной виртуальной машине, запись можно добавить:

```bash
sudo nano /etc/fstab
```

Если команда `nano` отсутствует:

```bash
sudo apt update
```

```bash
sudo apt install nano
```

После редактирования обязательно:

```bash
sudo findmnt --verify
```

# Шаг 6. Проверьте настройку без перезагрузки

Если диск уже смонтирован, сначала выйдите из него:

```bash
cd ~
```

Размонтируйте:

```bash
sudo umount /mnt/data
```

Проверьте:

```bash
findmnt /mnt/data
```

Теперь примените `/etc/fstab`:

```bash
sudo mount -a
```

Проверьте:

```bash
findmnt /mnt/data
```

И:

```bash
df -hT /mnt/data
```

Если диск снова появился в `/mnt/data`, постоянная конфигурация работает.

# Для студентов, которые работают непосредственно на Linux

Если Ubuntu или другой Linux установлен непосредственно на компьютере, используйте сценарий A.

Подключите USB-флешку физически и определите ее через:

```bash
lsblk
```

```bash
lsblk -f
```

```bash
lsblk -o NAME,MODEL,SIZE,TYPE,FSTYPE,LABEL,TRAN,MOUNTPOINTS
```

Не ориентируйтесь только на название устройства.

Нельзя считать, что флешка обязательно будет:

```text
/dev/sdb
```

На конкретной системе она может оказаться:

```text
/dev/sdc
```

или иметь другое имя.

Перед любыми действиями обязательно выполните:

```bash
findmnt /
```

и убедитесь, что выбранное устройство не относится к корневой файловой системе.

# Советы по улучшению работы

Не копируйте названия устройств из примеров. `/dev/sdb1` используется в задании только как пример. На вашей системе устройство может называться иначе.

Перед любой операцией с диском сначала выполняйте:

```bash
lsblk
```

и:

```bash
findmnt /
```

Это позволяет не перепутать учебный накопитель с системным диском.

Старайтесь использовать для диагностики несколько команд совместно. Например:

```bash
lsblk -f
```

показывает файловые системы и точки монтирования,

```bash
blkid
```

показывает UUID,

```bash
findmnt
```

подтверждает реальное монтирование,

```bash
df
```

показывает состояние файловой системы,

а:

```bash
du
```

показывает объем конкретных файлов и каталогов.

Не исправляйте ошибки доступа командой:

```bash
chmod 777
```

без анализа причины. Сначала определите:

```bash
ls -ld /mnt/usb
```

```bash
whoami
```

```bash
id
```

и тип файловой системы:

```bash
lsblk -f
```

При работе с `ext4` права и владельцы являются частью файловой системы.

При работе с FAT или exFAT права могут задаваться параметрами монтирования.

Не перезагружайте удаленную Ubuntu сразу после изменения `/etc/fstab`.

Сначала используйте:

```bash
sudo findmnt --verify
```

и при необходимости:

```bash
sudo mount -a
```

При работе по SSH всегда учитывайте, что ошибка в настройке дисков может повлиять на доступность удаленной системы.

Главный принцип этой практической работы:

```text
сначала определить устройство
→ проверить, что оно не системное
→ определить файловую систему
→ определить UUID
→ смонтировать
→ проверить монтирование
→ проверить права
→ выполнить работу с файлами
→ корректно размонтировать
```

Результатом работы должно стать не просто выполнение набора команд, а понимание связи между устройством, разделом, файловой системой, точкой монтирования, свободным пространством и правами пользователя.
