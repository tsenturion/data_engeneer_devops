# Практическое задание

# Проектирование и реализация таблиц в MS SQL Server

## Цель

Разработать структуру базы данных для реальной предметной области, определить набор таблиц, выбрать подходящие типы данных, организовать хранение информации с использованием схем и выполнить базовые операции управления созданными объектами.

В рамках работы необходимо не просто создать набор таблиц, а спроектировать структуру так, чтобы она была понятной для дальнейшего развития системы, расширения функциональности и работы с большими объемами данных.

В качестве предметной области необходимо выбрать один из вариантов:

- интернет-магазин;
- система управления учебным центром;
- сервис бронирования;
- медицинская информационная система;
- система управления проектами;
- банковская система;
- служба доставки;
- социальная сеть;
- собственная предметная область после согласования.

---

# Задание

Необходимо создать новую базу данных и спроектировать структуру хранения информации.

## 1. Создание структуры базы данных

Создать отдельную базу данных для проекта.

Название базы данных должно отражать выбранную предметную область.

Например:

```sql
CREATE DATABASE ONLINESTOREDB;
```

После создания выполнить подключение к новой базе данных и продолжить работу внутри нее.

---

## 2. Проектирование схем базы данных

Создать несколько схем для разделения объектов по назначению.

Минимально необходимо использовать:

- схему для основных данных;
- схему для пользователей или учетных записей;
- схему для справочной информации.

Например:

```sql
CREATE SCHEMA Catalog;

CREATE SCHEMA Users;

CREATE SCHEMA Reference;
```

Распределить будущие таблицы между созданными схемами.

---

## 3. Разработка таблиц

Создать минимум 6 таблиц.

Количество и назначение таблиц должны соответствовать выбранной предметной области.

Например, для интернет-магазина:

```
Catalog.Products

Catalog.Orders

Catalog.OrderItems

Users.Customers

Reference.Categories

Reference.PaymentMethods
```

Каждая таблица должна содержать:

- уникальный идентификатор;
- основные поля сущности;
- корректно выбранные типы данных;
- ограничения целостности.

---

## 4. Выбор типов данных

Для каждого поля определить подходящий тип данных.

Необходимо использовать разные типы данных в зависимости от назначения информации.

В проекте должны присутствовать:

- числовые значения;
- строки;
- даты и время;
- логические значения;
- идентификаторы.

Пример:

```sql
CREATE TABLE Catalog.Products
(
    ProductId INT IDENTITY(1,1),
    ProductName NVARCHAR(200),
    Price DECIMAL(10,2),
    CreatedDate DATETIME2,
    IsActive BIT
);
```

Необходимо избегать универсального подхода, когда все значения хранятся одним типом данных.

---

## 5. Добавление ограничений

Для созданных таблиц определить необходимые ограничения:

- первичные ключи;
- внешние ключи;
- ограничения уникальности;
- проверки допустимых значений.

Пример:

```sql
ALTER TABLE Catalog.Products
ADD Constraint PK_PRODUCTS
PRIMARY KEY (Productid);
```

Для связанных таблиц определить связи.

Например:

товар относится к категории;

заказ содержит товары;

пользователь создает заказ.

---

## 6. Заполнение таблиц тестовыми данными

Добавить тестовые данные в созданные таблицы.

Минимально:

- 10 записей для основных таблиц;
- 5 записей для справочных таблиц.

Пример:

```sql
INSERT INTO Reference.Categories (Name)
VALUES
('Ноутбуки'),
('Мониторы'),
('Комплектующие');
```

Данные должны выглядеть реалистично и позволять выполнять дальнейшие запросы.

---

## 7. Выполнение операций над таблицами

Выполнить операции изменения структуры базы данных.

Необходимо:

создать новую таблицу;

добавить новый столбец;

изменить тип одного из существующих столбцов;

переименовать объект;

удалить временный объект.

Пример:

Добавление столбца:

```sql
ALTER TABLE Catalog.Products
ADD Description NVARCHAR (MAX);
```

---

## 8. Проверка созданной структуры

Получить информацию о созданных объектах.

Проверить:

- список таблиц;
- используемые схемы;
- структуру столбцов;
- ограничения.

Использовать системные представления SQL Server.

Например:

```sql
SELECT *
FROM sys.tables;
```

# Подсказки по ключевым частям

При проектировании таблиц сначала необходимо определить, какие объекты существуют в выбранной предметной области.

Например, в интернет-магазине отдельно существуют:

- покупатель;
- товар;
- категория;
- заказ;
- способ оплаты.

Не следует хранить всю информацию в одной большой таблице. Разделение данных по таблицам позволяет уменьшить дублирование информации и сделать структуру более удобной для дальнейшего развития.

При выборе типов данных необходимо учитывать не только текущий объем информации, но и возможное расширение системы.

Например, для денежных значений не стоит использовать обычный тип `INT`, так как стоимость может содержать дробную часть:

```sql
Price DECIMAL(10,2)
```

Для текстовых данных необходимо учитывать возможность хранения символов разных языков:

```sql
NVARCHAR
```

Для дат и времени предпочтительно использовать современные типы:

```sql
DATE

DATETIME2
```

При создании таблиц необходимо заранее продумать связи между сущностями.

Например, если одна категория содержит много товаров, достаточно хранить идентификатор категории в таблице товаров, а не повторять название категории в каждой строке.

Структура должна быть подготовлена так, чтобы в дальнейшем можно было добавлять индексы, процедуры, представления и выполнять оптимизацию запросов.

# Советы по улучшению работы

Не стоит создавать таблицы только для выполнения минимального требования. При проектировании базы данных необходимо учитывать дальнейшее развитие системы.

Хорошая структура базы данных должна позволять добавлять новые возможности без полной переработки существующих таблиц.

Следует заранее подумать, какие данные будут часто изменяться, какие значения являются справочниками, а какие относятся к основной информации.

При выборе названий объектов лучше использовать единый стиль. Например, все таблицы могут иметь одинаковый подход к именованию ключей:

```sql
CustomerId

ProductId

OrderId
```

Не рекомендуется использовать непонятные названия вроде:

```sql
Table1

Data2

Info
```

Перед созданием таблиц полезно проверить, нет ли лишнего дублирования информации. Если одно значение может измениться, лучше хранить его отдельно и связывать через идентификатор.

В дальнейшем эта структура будет основой для работы с индексами, оптимизацией запросов, транзакциями и анализом производительности базы данных, поэтому качество проектирования таблиц напрямую влияет на скорость и надежность будущей системы.
