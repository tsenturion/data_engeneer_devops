# Практическое задание

# Реализация управляемого кода в SQL Server

## Цель

Настроить интеграцию SQL Server с CLR, создать управляемый код на C#, скомпилировать его в .NET Framework-сборку, зарегистрировать сборку внутри базы данных и связать методы сборки с объектами SQL Server.

В рамках практической работы необходимо проверить состояние CLR на экземпляре SQL Server, включить выполнение пользовательского CLR-кода, исследовать параметр `clr strict security`, создать DLL-библиотеку, зарегистрировать ее как доверенную сборку, импортировать DLL через `CREATE ASSEMBLY`, создать скалярные CLR-функции и CLR-хранимую процедуру, проверить их работу и исследовать системные каталоги SQL Server.

Дополнительно необходимо сравнить обычную реализацию на T-SQL и реализацию части логики на C#, определить, какие задачи имеют смысл для CLR, а какие эффективнее и проще оставить на стороне SQL Server.

Основной результат работы — получить полный цикл:

```text
C# исходный код

компиляция DLL

регистрация доверия к сборке

CREATE ASSEMBLY

создание SQL-объектов

выполнение CLR-кода внутри SQL Server
```

Работу выполнять только на учебном или локальном экземпляре SQL Server.

```sql

```

Зафиксировать результат.

На современных версиях SQL Server ожидается:

```text

```

Отключать эту настройку в рамках практической работы не требуется.

Начиная с SQL Server 2017, `clr strict security` включён по умолчанию. При такой настройке SQL Server не рассматривает `SAFE` как полноценную границу безопасности и требует дополнительного доверия к пользовательской сборке. # 7. Создание первой CLR-функции

Создать файл:

```text
TextFunctions.cs
```

Добавить реальный C#-код:

```csharp
using System.Data.SqlTypes;
using System.Text.RegularExpressions;
using Microsoft.SqlServer.Server;

namespace SqlClrLab
{
    public static class TextFunctions
    {
        [SqlFunction(IsDeterministic = true, IsPrecise = true)]
        public static SqlString NormalizePhone(SqlString value)
        {
            // Возвращаем NULL, если входное значение отсутствует.
            if (value.IsNull)
            {
                return SqlString.Null;
            }

            // Оставляем в строке только цифры.
            string result = Regex.Replace(
                value.Value,
                @"[^0-9]",
                string.Empty
            );

            return new SqlString(result);
        }
    }
}
```

Функция будет принимать номер телефона:

```text
+7 (999) 123-45-67
```

и возвращать:

```text
79991234567
```

# 8. Добавление второй CLR-функции

В тот же класс добавить:

```csharp
[SqlFunction(IsDeterministic = true, IsPrecise = true)]
public static SqlInt32 CountDigits(SqlString value)
{
    // Для NULL возвращаем NULL.
    if (value.IsNull)
    {
        return SqlInt32.Null;
    }

    int count = 0;

    foreach (char symbol in value.Value)
    {
        if (char.IsDigit(symbol))
        {
            count++;
        }
    }

    return new SqlInt32(count);
}
```

Итоговый класс должен содержать обе функции.

Первая:

```text
NormalizePhone
```

нормализует номер.

Вторая:

```text
CountDigits
```

подсчитывает количество цифр в строке.

# 9. Создание CLR-хранимой процедуры

Создать файл:

```text
Procedures.cs
```

Добавить:

```csharp
using System.Data.SqlTypes;
using Microsoft.SqlServer.Server;

namespace SqlClrLab
{
    public static class Procedures
    {
        [SqlProcedure]
        public static void ShowMessage(SqlString message)
        {
            // Отправляем результат вызывающему клиенту SQL Server.
            if (message.IsNull)
            {
                SqlContext.Pipe.Send("Получено значение NULL.");
                return;
            }

            SqlContext.Pipe.Send(
                "Сообщение из CLR: " + message.Value
            );
        }
    }
}
```

Эта процедура не обращается к внешним ресурсам. Она просто демонстрирует выполнение управляемого кода непосредственно внутри процесса SQL Server.

# 10. Создание CLR-процедуры с доступом к базе данных

Добавить необходимые пространства имен:

```csharp
using System.Data;
using System.Data.SqlClient;
```

Добавить второй метод:

```csharp
[SqlProcedure]
public static void GetCustomerCount()
{
    // Контекстное соединение работает внутри текущего подключения SQL Server.
    using (SqlConnection connection =
           new SqlConnection("context connection=true"))
    {
        connection.Open();

        using (SqlCommand command = new SqlCommand(
            @"SELECT COUNT(*) AS CustomerCount
              FROM Data.Customers;",
            connection))
        {
            SqlContext.Pipe.ExecuteAndSend(command);
        }
    }
}
```

В результате управляемый код будет выполнять SQL-запрос через контекстное соединение.

# 17. Регистрация сборки как доверенной

При включенном:

```text
clr strict security = 1
```

неподписанная сборка не должна загружаться только на основании `PERMISSION_SET = SAFE`.

Для лабораторной работы использовать список доверенных сборок.

Полученный SHA-512 преобразовать в бинарный литерал SQL Server:

```text
0xВАШ_SHA512_БЕЗ_ПРОБЕЛОВ
```

Выполнить из учетной записи с правами `sysadmin` или `CONTROL SERVER`:

```sql
EXEC sys.sp_add_trusted_assembly
    @hash = 0xЗДЕСЬ_ФАКТИЧЕСКИЙ_SHA512,
    @description = N'SqlClrLab учебная сборка';
GO
```

Здесь нельзя буквально оставлять:

```text
ЗДЕСЬ_ФАКТИЧЕСКИЙ_SHA512
```

Необходимо вставить фактический SHA-512 своей DLL.

`sys.sp_add_trusted_assembly` позволяет доверенной сборке загружаться при включённом `clr strict security`.

# 34. Создание альтернативной реализации на T-SQL

Для одной простой задачи создать T-SQL-аналог.

Например, подсчет длины строки или другая простая операция.

Для нормализации телефона можно создать учебную функцию:

```sql
CREATE FUNCTION App.tsql_NormalizePhone
(
    @value NVARCHAR(4000)
)
RETURNS NVARCHAR(4000)
AS
BEGIN
    IF @value IS NULL
        RETURN NULL;

    SET @value = REPLACE(@value, N'+', N'');
    SET @value = REPLACE(@value, N'(', N'');
    SET @value = REPLACE(@value, N')', N'');
    SET @value = REPLACE(@value, N'-', N'');
    SET @value = REPLACE(@value, N' ', N'');

    RETURN @value;
END;
GO
```

Проверить:

```sql
SELECT App.tsql_NormalizePhone(
    N '+7 (999) 123-45-67'
);
```

# 41. Изменение исходного C#-кода

Изменить:

```text
NormalizePhone
```

так, чтобы функция, например, возвращала:

```text
NULL
```

для строки, в которой не найдено ни одной цифры.

Пример:

```csharp
[SqlFunction(IsDeterministic = true, IsPrecise = true)]
public static SqlString NormalizePhone(SqlString value)
{
    // Обрабатываем SQL NULL.
    if (value.IsNull)
    {
        return SqlString.Null;
    }

    string result = Regex.Replace(
        value.Value,
        @"[^0-9]",
        string.Empty
    );

    // Пустой результат считаем отсутствующим номером.
    if (result.Length == 0)
    {
        return SqlString.Null;
    }

    return new SqlString(result);
}
```

# Подсказки по ключевым частям

SQL CLR позволяет запускать управляемый .NET-код непосредственно внутри SQL Server.

Это не означает, что SQL Server превращается в обычное приложение C#.

CLR-интеграция предназначена для определенного набора серверных объектов. На базе управляемой assembly SQL Server может создавать, в частности, хранимые процедуры, функции, триггеры, пользовательские типы и пользовательские агрегаты.

Для CLR-кода SQL Server используется .NET Framework.

Не следует создавать для этой практики обычный современный проект:

```text
.NET 8
```

или:

```text
.NET 10
```

и ожидать, что SQL Server сможет загрузить такую DLL.

SQL CLR не поддерживает .NET Core и .NET 5+ как CLR-среду SQL Server.

Связь между C# и SQL Server состоит из двух уровней.

Сначала DLL регистрируется:

```sql
CREATE ASSEMBLY SqlClrLab
FROM '...';
```

После этого конкретный SQL-объект связывается с методом:

```sql
AS EXTERNAL NAME
    SqlClrLab.[SqlClrLab.TextFunctions].NormalizePhone;
```

Само наличие DLL в базе еще не создает:

```text
FUNCTION
PROCEDURE
TRIGGER
```

Это отдельные SQL-объекты.

В конструкции:

```text
Assembly.Class.Method
```

необходимо точно соблюдать имена.

Если C# содержит:

```csharp
namespace SqlClrLab
{
    public static class TextFunctions
    {
        public static SqlString NormalizePhone(...)
```

то SQL-ссылка имеет вид:

```sql
SqlClrLab.[SqlClrLab.TextFunctions].NormalizePhone
```

Первая часть:

```text
SqlClrLab
```

— имя assembly внутри SQL Server.

Вторая:

```text
SqlClrLab.TextFunctions
```

— namespace и class.

Третья:

```text
NormalizePhone
```

— метод.

Особенно важно понимать современную безопасность SQL CLR.

Старые учебные материалы могут рекомендовать:

```sql
EXEC sp_configure 'clr strict security', 0;
```

или:

```sql
ALTER DATABASE ...
SET TRUSTWORTHY ON;
```

только для того, чтобы неподписанная DLL быстрее загрузилась.

В этой работе такой подход не используется.

`clr strict security` включен по умолчанию в SQL Server 2017 и более новых версиях, а Microsoft не рекомендует отключать его. Предпочтительный производственный подход — подпись assembly сертификатом или асимметричным ключом. Для лабораторного контролируемого сценария можно использовать список доверенных сборок через `sys.sp_add_trusted_assembly`.

Нельзя считать:

```sql
PERMISSION_SET = SAFE
```

достаточным доказательством того, что произвольная DLL безопасна.

Именно поэтому сначала необходимо понимать происхождение assembly, а уже затем предоставлять SQL Server возможность ее выполнить.

Никогда не импортируйте случайную DLL из интернета в SQL Server только потому, что она объявлена как:

```text
SAFE
```

В рабочей системе сборка должна проходить контроль исходного кода, процесса сборки, подписи и развертывания.

Управляемый код особенно интересен там, где C# значительно выразительнее T-SQL.

Хороший учебный пример:

```text
Regex
```

Регулярное выражение:

```csharp
Regex.Replace(
    value,
    @"[^0-9]",
    string.Empty
);
```

позволяет компактно выразить преобразование, которое на чистом T-SQL может потребовать значительно более громоздкой логики.

Это не означает, что регулярное выражение всегда быстрее.

Удобство программирования и производительность — разные характеристики.

Если задача заключается в:

```text
соединении таблиц;
фильтрации;
группировке;
агрегировании;
массовом обновлении;
```

T-SQL обычно естественнее, потому что SQL Server оптимизирует эти операции как работу с наборами данных.

Не следует переносить в C# запрос:

```sql
SELECT
    CUSTOMERID,
    COUNT(*)
FROM DATA.CUSTOMERS
GROUP BY CUSTOMERID;
```

только ради того, чтобы использовать CLR.

При обращении из SQL CLR к текущей базе можно использовать:

```csharp
"context connection=true"
```

Это специальное контекстное соединение, предназначенное для SQL CLR-кода внутри SQL Server.

Оно позволяет управляемому модулю работать в текущем серверном контексте.

При проектировании CLR-функций особенно внимательно относитесь к использованию функции для каждой строки огромной таблицы.

Запрос:

```sql
SELECT App.clr_NormalizePhone(Phone)
FROM Data.Customers;
```

при четырех строках практически ничего не говорит о производительности.

На таблице из:

```text
10 000
100 000
1 000 000 строк
```

стоимость большого количества вызовов становится намного важнее.

Поэтому в практической работе предусмотрено отдельное сравнение.

Не следует считать CLR универсальным способом ускорения SQL Server.

Иногда CLR будет:

```text
удобнее;
компактнее;
выразительнее.
```

Но обычный T-SQL может оказаться производительнее или значительно проще для эксплуатации.

Архитектурное решение должно учитывать:

```text
сложность алгоритма;
частоту выполнения;
объем данных;
требования безопасности;
сложность развертывания;
сопровождение DLL;
необходимость пересборки;
наличие аналогичного решения на T-SQL.
```

# Советы по улучшению работы

Не начинайте SQL CLR с отключения механизмов безопасности. Если `CREATE ASSEMBLY` завершается ошибкой при включенном `clr strict security`, сначала определите причину ошибки и настройте доверие к собственной сборке.

Не используйте:

```sql
ALTER DATABASE SqlClrPracticeDB
SET TRUSTWORTHY ON;
```

как стандартный способ решения проблемы импорта assembly.

Для учебной собственной DLL значительно лучше осознанно зарегистрировать конкретный SHA-512 или использовать подпись assembly.

Не используйте:

```sql
EXEC sp_configure 'clr strict security', 0;
```

только потому, что так проще выполнить старую инструкцию из интернета. Современная документация Microsoft прямо не рекомендует отключать эту настройку.

Не путайте файл DLL на диске и assembly внутри базы.

После:

```sql
CREATE ASSEMBLY
```

SQL Server регистрирует содержимое assembly в базе данных. Файл используется как источник при развертывании.

Не изменяйте DLL и не ожидайте, что код внутри SQL Server изменится автоматически. После пересборки требуется контролируемое обновление assembly.

Не создавайте CLR-код ради обычных операций реляционной базы данных. Если задача естественно выражается одним `SELECT`, `JOIN`, `GROUP BY` или `UPDATE`, сначала используйте T-SQL.

Рассматривайте CLR, когда управляемый язык действительно предоставляет существенное преимущество.

Например, регулярные выражения являются хорошим учебным примером, потому что .NET предоставляет готовую развитую библиотеку:

```csharp
System.Text.RegularExpressions
```

Не выполняйте из CLR длительные сетевые операции без серьезного архитектурного обоснования. Код запускается внутри SQL Server, поэтому его ошибки и задержки способны влиять на сервер базы данных.

Избегайте тяжелых вычислений в CLR-функции, вызываемой для миллионов строк, без тестирования.

Всегда сравнивайте альтернативы.

Например:

```text
CLR Function

T-SQL expression

T-SQL scalar function

computed column

предварительная обработка в приложении
```

могут решать похожую прикладную задачу, но иметь разную стоимость эксплуатации.

В производственной системе DLL должна иметь управляемый жизненный цикл:

```text
исходный код;
репозиторий;
сборка;
версия;
проверка;
подпись или доверие;
развертывание;
обновление;
откат.
```

Не следует вручную заменять DLL на сервере без понимания того, какая версия зарегистрирована в базе данных.

Итоговая работа считается качественно выполненной, если CLR был включен без ослабления `clr strict security`, собственная .NET Framework-сборка успешно скомпилирована и зарегистрирована, методы C# опубликованы как SQL Server функции и процедуры, исследованы системные каталоги, а выбор CLR для конкретной задачи обоснован сравнением с обычным T-SQL.
