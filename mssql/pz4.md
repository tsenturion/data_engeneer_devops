# Практическое задание

# Поддержание целостности данных через ограничения в MS SQL Server

## Цель

Разработать структуру базы данных, в которой обеспечивается корректность, надежность и согласованность информации с помощью ограничений целостности.

В рамках работы необходимо создать таблицы с различными типами ограничений, проверить защиту данных от некорректного ввода и реализовать правила, которые будут контролировать допустимые значения, уникальность записей и корректность связей между объектами базы данных.

Задача работы — подготовить структуру базы данных, где контроль качества данных выполняется не только на уровне приложения, но и непосредственно внутри СУБД.

---

# Задание

Необходимо разработать базу данных для выбранной предметной области.

В качестве примера можно использовать:

- интернет-магазин;
- систему управления сотрудниками;
- образовательную платформу;
- систему учета клиентов;

- систему управления проектами.

Необходимо создать минимум 5 связанных таблиц и реализовать разные виды ограничений целостности.

# 3. Реализация сущностной целостности

Для каждой основной таблицы создать первичный ключ.

Первичный ключ должен:

- однозначно определять запись;
- не допускать повторений;
- не содержать пустых значений.

Пример:

```sql
CREATE TABLE Application.Students
(
    StudentId INT IDENTITY(1,1)
        CONSTRAINT PK_Students PRIMARY KEY,

    FullName NVARCHAR(200)
);
```

Проверить работу ограничения:

Попытаться добавить две записи с одинаковым идентификатором.

Создать ограничения CHECK.

Пример:

```sql

```

# 5. Реализация ссылочной целостности

Создать связи между таблицами с помощью внешних ключей.

Например:

Один студент может иметь несколько записей о прохождении курсов.

Создать внешний ключ:

```sql
CREATE TABLE Application.Enrollments
(
    EnrollmentId INT IDENTITY(1,1)
        CONSTRAINT PK_Enrollments PRIMARY KEY,

    StudentId INT,

    CONSTRAINT FK_Enrollments_Students
    FOREIGN KEY(StudentId)
    REFERENCES Application.Students(StudentId)
);
```

Проверить:

- нельзя добавить запись с несуществующим идентификатором;
- нельзя удалить объект, который используется в других таблицах.

# Подсказки по ключевым частям

При проектировании ограничений необходимо учитывать, какие правила относятся к самой таблице, а какие связаны с другими объектами.

Например, правило:

«Возраст пользователя должен быть больше 18»

относится к значениям внутри одной таблицы и реализуется через `CHECK`.

А правило:

«Заказ должен принадлежать существующему клиенту»

связано с несколькими таблицами и реализуется через внешний ключ.

Не следует полностью переносить контроль данных на уровень приложения. Если база данных используется несколькими системами, ограничения внутри СУБД позволяют сохранять единые правила независимо от источника данных.

Первичный ключ должен быть у каждой таблицы, которая хранит самостоятельные сущности.

Например:

- клиент;
- товар;
- сотрудник;
- заказ.

Внешние ключи необходимо создавать там, где одна сущность зависит от другой.

Например:

заказ зависит от клиента;

платеж зависит от заказа;

запись на курс зависит от студента и курса.

При создании ограничений важно выбирать правильную логику.

Например, не каждое удаление должно быть каскадным. Для финансовых операций или исторических данных чаще необходимо запрещать удаление, чтобы сохранить информацию.

# Советы по улучшению работы

При проектировании базы данных необходимо создавать ограничения сразу вместе со структурой таблиц, а не добавлять их после появления проблем с данными.

Хорошая база данных должна самостоятельно предотвращать появление некорректной информации.

Например, если поле электронной почты должно быть уникальным, лучше создать ограничение `UNIQUE`, чем рассчитывать только на проверку в приложении.

Не следует создавать слишком жесткие ограничения без понимания бизнес-логики. Например, ограничение `CHECK` с неправильным условием может заблокировать реальные операции пользователей.

Перед добавлением ограничения необходимо определить:

- какие данные являются обязательными;
- какие значения допустимы;
- какие записи могут существовать независимо;
- какие объекты зависят друг от друга.

При проектировании высоконагруженных систем качество ограничений напрямую влияет на надежность базы данных. Правильно созданная структура помогает обнаруживать ошибки на этапе записи данных и предотвращает накопление некорректной информации.
