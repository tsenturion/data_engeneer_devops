# Практическое задание: исследование внутренней работы PostgreSQL

## Цель

На практике исследовать, как PostgreSQL хранит и обрабатывает данные, как работают транзакции, блокировки, версии строк, буферный кеш, WAL, контрольные точки, очистка и сбор статистики.

В результате должна получиться одна учебная база с таблицами и SQL-скриптом, который демонстрирует основные механизмы из модулей 4–6.

## Задание

### Шаг 1. Создайте отдельную схему для практики

Создайте схему:

```text
postgres_lab
```

Все пользовательские таблицы практической работы размещайте внутри этой схемы.

После создания выполните запрос, который проверяет существование схемы.

### Шаг 2. Создайте таблицу счетов

Создайте таблицу:

```text
postgres_lab.accounts
```

В ней должны находиться столбцы:

```text
id
owner_name
balance
created_at
```

Требования:

- `id` — первичный ключ;
- `owner_name` — текст;
- `balance` — числовое значение;
- `created_at` — дата и время создания строки;
- для `created_at` должно использоваться значение по умолчанию.

Добавьте не менее 10 строк.

### Шаг 3. Создайте таблицу с крупными текстовыми данными

Создайте таблицу:

```text
postgres_lab.documents
```

Она должна содержать идентификатор документа, название и большое текстовое поле.

Добавьте несколько небольших документов и минимум один документ с очень большим текстом. Большой текст сформируйте средствами PostgreSQL, а не копируйте вручную.

Например, для генерации данных можно использовать функцию:

```sql
repeat()
```

После вставки определите размер каждого текстового значения.

### Шаг 4. Исследуйте физическое хранение таблиц

Напишите SQL-запросы, которые для таблиц `accounts` и `documents` показывают:

- размер самой таблицы;
- общий размер таблицы вместе с дополнительными объектами;
- физический путь к файлу отношения;
- табличное пространство, в котором находится объект.

Используйте системные функции PostgreSQL.

После этого определите, где физически расположена база данных внутри каталога кластера.

### Шаг 5. Исследуйте TOAST

Для таблицы `documents` определите, существует ли связанная с ней TOAST-таблица.

Получите имя TOAST-отношения через системный каталог PostgreSQL.

Сравните размер основной таблицы и полный размер отношения после добавления большого текста.

Сделайте SQL-комментарий в файле с объяснением, почему размер полного отношения может отличаться от размера основной таблицы.

### Шаг 6. Исследуйте страницы таблицы

Используйте расширение:

```text
pageinspect
```

Проверьте, установлено ли оно в текущей базе.

Для таблицы `accounts` получите информацию о первой странице таблицы.

Затем получите информацию о версиях строк, находящихся внутри этой страницы.

В результат должны попасть как минимум следующие характеристики:

```text
lp
lp_off
lp_len
t_xmin
t_xmax
t_ctid
```

Не изменяйте содержимое страниц вручную.

### Шаг 7. Исследуйте буферный кеш

Используйте расширение:

```text
pg_buffercache
```

Сначала выполните несколько запросов к таблице `accounts`.

После этого получите общую информацию о состоянии буферного кеша.

Затем напишите запрос, который подсчитывает количество чистых и измененных буферов.

Дополнительно определите, присутствуют ли страницы таблицы `accounts` в `pg_buffercache`.

### Шаг 8. Исследуйте статистику выполнения запросов

Используйте:

```text
pg_stat_statements
```

Выполните несколько разных запросов к таблице `accounts`, причем один из запросов запустите несколько раз.

После этого получите статистику и выведите:

```text
query
calls
total_exec_time
mean_exec_time
rows
```

Отсортируйте результат так, чтобы наиболее затратные запросы находились сверху.

Ограничьте результат десятью строками.

### Шаг 9. Исследуйте WAL

Получите текущую позицию WAL.

После этого выполните несколько операций изменения данных:

```text
INSERT
UPDATE
DELETE
```

Повторно получите позицию WAL.

В SQL-комментарии укажите, изменилась ли позиция после операций записи.

Также получите значения параметров:

```text
wal_buffers
min_wal_size
max_wal_size
```

### Шаг 10. Выполните контрольную точку

Получите статистику работы checkpointer.

Затем вручную выполните:

```sql
CHECKPOINT;
```

После этого снова получите статистику checkpointer и сравните результаты.

Не изменяйте параметры checkpoint в конфигурационном файле.

### Шаг 11. Исследуйте версии строк

Выберите одну строку из таблицы `accounts` и получите для нее:

```text
ctid
xmin
xmax
```

После этого измените строку командой `UPDATE`.

Повторите запрос к системным столбцам.

В SQL-комментарии укажите, какие значения изменились.

### Шаг 12. Проверьте работу транзакции

Начните явную транзакцию.

Внутри нее:

```text
добавьте новую строку;
измените существующую строку;
удалите одну строку.
```

До завершения транзакции проверьте результат.

Затем выполните:

```sql
ROLLBACK;
```

Проверьте состояние таблицы после отката.

После этого повторите аналогичную последовательность, но завершите ее через:

```sql
COMMIT;
```

### Шаг 13. Используйте SAVEPOINT

Создайте транзакцию, внутри которой выполните несколько изменений.

Между операциями создайте:

```sql
SAVEPOINT
```

После этого отмените только часть изменений через:

```sql
ROLLBACK TO SAVEPOINT
```

Оставшуюся часть транзакции зафиксируйте.

Проверьте итоговое состояние таблицы.

### Шаг 14. Исследуйте уровень изоляции

Получите текущий уровень изоляции.

Затем запустите транзакцию:

```text
REPEATABLE READ
```

Для этого этапа понадобятся два соединения PostgreSQL.

В первом соединении прочитайте выбранную строку.

Во втором соединении измените эту строку и выполните `COMMIT`.

После этого снова прочитайте строку в первом соединении до завершения его транзакции.

Затем завершите первую транзакцию и выполните новый `SELECT`.

Добавьте комментарий с наблюдаемым результатом.

### Шаг 15. Исследуйте блокировку строки

Работу также выполняйте в двух соединениях.

В первом соединении:

```sql
BEGIN;
```

Затем получите строку через:

```sql
SELECT ...
FOR UPDATE;
```

Транзакцию пока не завершайте.

Во втором соединении попробуйте изменить ту же строку.

Пока запрос находится в ожидании, в отдельном соединении получите информацию из:

```text
pg_locks
pg_stat_activity
```

Также используйте:

```sql
pg_blocking_pids()
```

Определите PID блокирующего и заблокированного процессов.

После исследования завершите первую транзакцию.

### Шаг 16. Исследуйте блокировку таблицы

Начните новую транзакцию и установите на `accounts` блокировку:

```text
ACCESS EXCLUSIVE
```

В другом соединении попробуйте выполнить обычный `SELECT`.

Получите информацию об ожидающих и предоставленных блокировках.

После проверки обязательно завершите транзакцию.

### Шаг 17. Создайте мертвые версии строк

Добавьте в таблицу несколько тысяч строк. Данные можно генерировать через:

```sql
generate_series()
```

После этого выполните массовый `UPDATE`, а затем удалите часть строк.

Получите статистику таблицы из:

```text
pg_stat_user_tables
```

Выведите как минимум:

```text
n_live_tup
n_dead_tup
last_vacuum
last_autovacuum
```

### Шаг 18. Выполните очистку

Сначала получите размер таблицы.

Затем выполните:

```sql
VACUUM
```

Повторно получите статистику таблицы и ее размер.

Сделайте комментарий о том, уменьшился ли физический файл таблицы после обычного `VACUUM`.

После этого выполните:

```sql
VACUUM FULL
```

Снова проверьте размер.

### Шаг 19. Исследуйте заморозку

Получите значения:

```text
vacuum_freeze_min_age
autovacuum_freeze_max_age
```

После этого выполните для учебной таблицы:

```sql
VACUUM FREEZE
```

Получите возраст `relfrozenxid` для таблицы.

Также получите возраст `datfrozenxid` для текущей базы.

### Шаг 20. Выполните ANALYZE

До выполнения анализа получите статистику таблицы.

Затем выполните:

```sql
ANALYZE postgres_lab.accounts;
```

После этого получите:

```text
last_analyze
last_autoanalyze
```

из `pg_stat_user_tables`.

Дополнительно найдите строки для таблицы `accounts` в:

```text
pg_stats
```

Выведите имя столбца, долю `NULL`, количество различных значений и наиболее частые значения там, где такая статистика существует.

### Шаг 21. Сравните план выполнения запроса

Выполните:

```sql
EXPLAIN
```

для запроса с условием по одному из столбцов таблицы `accounts`.

После этого выполните `ANALYZE`, а затем повторите `EXPLAIN`.

Сохраните оба результата в виде SQL-комментариев либо отдельного текстового блока в конце файла.

Если планы совпали, это не считается ошибкой. Необходимо только зафиксировать результат наблюдения.

## Подсказки по ключевым частям

Для исследования размеров и файлов могут пригодиться функции:

```sql
pg_relation_size()
pg_total_relation_size()
pg_relation_filepath()
pg_size_pretty()
```

Для исследования внутренних объектов пригодятся:

```text
pg_class
pg_database
pg_tablespace
pg_stat_user_tables
pg_stats
```

Для транзакций и версий строк обратите внимание на:

```text
xmin
xmax
ctid
pg_current_xact_id_if_assigned()
pg_current_snapshot()
```

Для блокировок используйте:

```text
pg_locks
pg_stat_activity
pg_blocking_pids()
```

Для WAL и контрольных точек пригодятся:

```text
pg_current_wal_lsn()
pg_stat_checkpointer
CHECKPOINT
```

Для генерации большого количества учебных данных можно использовать:

```sql
generate_series()
```

Не вставляйте тысячи строк вручную.

Расширения должны быть доступны на сервере и созданы в той базе, где выполняется работа:

```sql
CREATE EXTENSION pageinspect;
CREATE EXTENSION pg_buffercache;
CREATE EXTENSION pg_stat_statements;
```

Если расширение уже создано, повторно создавать его не требуется.

## Советы по улучшению работы

Разделите SQL-файл комментариями по этапам работы, чтобы было понятно, к какой части практического задания относится каждый запрос.

Не ограничивайтесь только командами изменения данных. После каждого значимого действия добавляйте диагностический запрос, который позволяет проверить результат.

Для работы с блокировками заранее откройте два или три соединения PostgreSQL. Одно соединение используется для удержания транзакции, второе — для создания конфликтующей операции, третье — для диагностики через `pg_locks` и `pg_stat_activity`.

Для массового заполнения таблиц используйте `generate_series()`. Это позволит получить заметное количество данных без ручной вставки сотен строк.

Не выполняйте `VACUUM FULL`, `CHECKPOINT` и ручные строгие блокировки на рабочей базе. В рамках задания они предназначены только для учебного стенда.

Итоговый файл назовите:

```text
postgres_modules_4_6_practice.sql
```

В нем должны находиться весь SQL-код, комментарии с результатами наблюдений и команды проверки выполненных этапов.
